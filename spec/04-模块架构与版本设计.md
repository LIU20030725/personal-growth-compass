# Dice Life 冒险日志模块架构与版本设计

**版本：** 1.0
**日期：** 2026-08-01
**状态：** 已确认，待书面规格复核
**分支：** `codex/adventure-journal/main`

## 1. 目标与依据

本设计把已确认的冒险日志玩法和 UI 美术方向转化为可实施的模块架构，并建立能够持续更新、迁移和发布的版本体系。

设计依据：

- [`01-冒险日志-PRD.md`](./01-冒险日志-PRD.md)
- [`02-UI美术设计.md`](./02-UI美术设计.md)
- [`STYLE.md`](../STYLE.md)
- [`PROJECT_CONTEXT.md`](../PROJECT_CONTEXT.md)
- [`任务模块 V2 设计`](../docs/superpowers/specs/2026-08-01-dice-life-task-module-v2-design.md)

当前技术基线为 React 18、TypeScript、Vite、Vitest、Testing Library、Lucide 和本地存储。设计时的基线验证为 8 个测试文件、37 项测试通过。

## 2. 已选方案

采用“版本化纵向迭代”：先用 V0.1.0 打通完整业务链路，再增加内容和氛围能力，最终冻结 V1.0.0。

未选方案：

- 一次完成完整 V1：并行引入地图、信箱、音频、回顾、资产和迁移，难以区分领域错误、集成错误与视觉问题。
- 纯静态原型：无法验证骰子账本、投资幂等、数据恢复和迁移，不适合作为正式模块起点。

纵向迭代不改变完整 V1 范围，只改变交付顺序。所有版本使用同一份持续演进的源码。

## 3. 模块边界与目录

正式实现使用以下目录：

```text
src/adventure-journal/
├─ domain/          类型、状态机、投资、解锁、发现和阶段规则
├─ content/         地图、物件、旅行用品、价格和内容版本
├─ storage/         本地存储、备份、迁移和待处理操作恢复
├─ integrations/    任务骰子账本、任务历史和 App 外壳适配
├─ components/      可复用的旅途、家园和通用交互组件
├─ pages/           页面编排和视图模型连接
├─ assets/          原创像素图、声音和静态降级资源
├─ styles/          模块 Token、布局、动效和低动态样式
├─ tests/           领域、存储、组件与集成测试
└─ moduleVersion.ts 模块、schema 和内容版本常量
```

边界规则：

1. `domain/` 是纯 TypeScript，不依赖 React、DOM 或 localStorage。
2. `storage/` 只负责序列化、备份、迁移和恢复，不定义玩法价格。
3. `integrations/` 是唯一可以直接依赖任务模块或 App 外壳的目录。
4. 组件通过属性和回调接收状态，不直接读写 localStorage。
5. 地图、价格和发现属于 `content/`，与数据 schema 分开版本化。
6. 任务系统继续拥有骰子收入和余额来源；冒险日志不得维护第二份余额。

## 4. 核心数据模型

```ts
type AdventureJournalState = {
  schemaVersion: number;
  contentVersion: string;
  currentChapterId: string;
  viewingMapId: string;
  unlockedMapIds: string[];
  routeInvestments: InvestmentProgress[];
  homeInvestments: InvestmentProgress[];
  gearInvestments: InvestmentProgress[];
  discoveries: DiscoveryRecord[];
  unlockedItemIds: string[];
  stages: GrowthStage[];
  mailbox: MailboxState;
  operations: InvestmentOperation[];
  preferences: JournalPreferences;
};
```

关键区分：

- `currentChapterId` 决定真实成长阶段和下一条主线路线。
- `viewingMapId` 只决定当前观看场景；切换旧地图不改变阶段。
- `schemaVersion` 描述持久化结构。
- `contentVersion` 描述地图、价格、发现和美术内容。
- `moduleVersion` 描述面向发布的模块能力集合。

投资目标统一包含固定价格、已投入数量、开放条件和解锁状态。已开始投资的目标必须保存当时的固定价格，后续内容版本不能对其涨价。

## 5. 骰子账本与投资事务

骰子余额由任务系统现有交易计算。冒险日志通过账本适配器读取余额，并写入 `adventure-spend` 支出交易。每笔冒险支出必须包含：

- 唯一操作 ID。
- 目标类型。
- 目标 ID。
- 投入数量。
- 创建时间。

投资流程：

```text
读取最新余额
  → 校验目标是否开放、是否已完成
  → 限制投入不超过目标剩余需求
  → 校验余额
  → 持久化 pending 操作
  → 按操作 ID 幂等写入支出交易
  → 应用目标进度
  → 触发发现或解锁
  → 标记操作 applied
```

本地存储无法跨两个键提供原子事务，因此使用可恢复操作日志：

- 账本已有同一操作 ID 时，不得再次扣款。
- 账本已扣款但目标未更新时，启动恢复补齐目标进度。
- 待处理操作尚未扣款时，可以安全重试。
- 操作完成后保留最小审计信息，不立即删除。

## 6. 旅途状态机

```text
未开放 → 可投资 → 已达标待启程 → 当前地图 → 历史地图
```

规则：

- 只有当前主线的下一张地图可投资。
- 达到固定价格后只解锁一次，并进入“待启程”。
- 解锁不强制切换场景。
- 用户主动启程后才归档上一阶段并开启新阶段。
- 历史地图永久可观看，切换不会更改当前主线或统计区间。
- 25%、50%、75% 发现由累计路线进度确定性触发，不依赖在线时长、登录频率或随机概率。

## 7. 家园与收藏状态机

```text
图纸未获得 → 可投资 → 建设中 → 已解锁
```

- 玩家始终只有一个永久家园。
- 家园与旅途并行，不互设强制前置。
- 多个物件可以同时保存部分投入。
- 达标后只触发一次解锁。
- V0.1.0 使用固定位置；V1 不实现自由摆放编辑器。
- 旅行用品只有外观、动画或声音变化，不提供数值加成。

## 9. UI 与交互约束

- 保留项目既有 64px Header、256px Sidebar、浅灰白背景、2px 深色硬边框和实体硬阴影。
- 像素纪录片风格只进入旅途、家园、人物、发现和回忆层。
- 像素主舞台占冒险日志内容区约 75%–80%。
- 主状态浮层不得超过舞台约 20%，不设置永久大型右侧面板。
- 每个视图最多一个主操作；投资按钮使用项目金色主操作样式。
- 图标统一使用 Lucide 或原创 SVG，不用 emoji 代替功能图标。
- 触控目标至少 44×44px，键盘顺序与视觉顺序一致，焦点清晰可见。
- 投资、余额不足、解锁和错误不能只用颜色、声音或动画表达。
- 支持系统减少动态效果、音乐关闭、环境音关闭和界面音关闭。
- 页面不可见时暂停非必要动画和声音。

## 10. 原创像素资产与内容

资产按内容版本组织，不按发布版本复制整套组件代码：

```text
assets/maps/v0.1.0/sunny-trail/
assets/home/v0.1.0/
assets/characters/v0.1.0/
assets/audio/v0.3.0/
```

- 环境使用 16×16px 或 32×32px 网格。
- Sprite 使用统一整数倍尺寸和 `image-rendering: pixelated`。
- 首屏只加载当前地图；旧地图、家园和音频按需加载。
- 关键资源提供静态降级图；资源失败不得阻塞数值操作。
- 正式资产必须原创，不复刻特定游戏的角色、地图、图标或 UI 皮肤。

## 11. 异常与恢复

| 情况 | 行为 |
| --- | --- |
| 余额不足 | 不写支出，显示余额和差额 |
| 投入超过剩余需求 | 限制为剩余数量，并在确认前明确展示 |
| 重复点击或刷新 | 使用操作 ID 去重 |
| 扣款后中断 | 启动时从账本补齐目标进度 |
| 目标已更新但界面过期 | 重新读取状态，不再次播放强制解锁 |
| 场景资源失败 | 静态占位，投资和账本保持可用 |
| 音频失败 | 静默降级，保留用户开关状态 |
| 数据损坏 | 保存原始数据备份，再进入安全初始化或迁移恢复 |
| 跨页面余额变化 | 提交前重新读取余额，拒绝过期校验结果 |

## 12. 测试与验收

### 领域测试

- 固定价格和已开始目标价格冻结。
- 余额校验、部分投入、剩余量上限。
- 同一目标部分投入永久保存。
- 阈值发现一次触发。
- 地图、物件和用品一次解锁。
- 待启程、主动启程和历史地图切换。

### 存储测试

- 空状态、往返保存和 schema 迁移。
- 损坏原始数据备份。
- pending 操作恢复。
- 已扣款操作不重复扣款。
- 内容版本升级不改写已开始目标价格。

### 集成测试

- 任务奖励进入冒险日志余额。
- 冒险投资只产生一笔支出。
- 任务归档或删除后既有交易仍保留。
- 旧地图切换不改变成长阶段。
- App 主导航可进入冒险日志，其他模块继续可用。

### 组件与视觉验收

- 双页面切换、投资、地图目录、建设和信箱流程。
- 键盘操作、焦点、可访问名称和低动态模式。
- 1440px、1180px 和窄桌面检查，无横向溢出和关键遮挡。
- 主舞台、浮层、颜色、字体和硬边组件逐项对照 UI 规范。

### 发布命令

```text
npm test
npm run build
git diff --check
```

## 13. 版本管理

采用模块级语义版本：

- `moduleVersion`：用户可感知能力版本，例如 `0.1.0`。
- `schemaVersion`：持久化结构整数版本，必须配套迁移。
- `contentVersion`：地图、价格、发现和资产内容版本。
- Git 标签：`adventure-journal-v0.1.0`。

文件职责：

- `src/adventure-journal/moduleVersion.ts`：运行时版本常量。
- `spec/VERSION.md`：当前版本和兼容关系。
- `spec/CHANGELOG.md`：面向模块的变更历史。
- `spec/releases/vX.Y.Z/`：发布范围、迁移说明、验收命令和证据索引。

发布目录不得保存源码副本。历史实现由 Git commit 和 tag 负责，避免多份代码分叉。

## 15. 明确不做

- 不重做 App 全局 Header、Sidebar 或其他模块布局。
- 不实现骰子随机投掷、战斗、血量、数值装备或挂机奖励。
- 不实现排行榜、社交、商城、付费加速或奖励过期。
- 不实现分支地图、开放世界或完整自由摆放编辑器。
- 不通过复制多个版本源码目录保存历史。

## 16. 规格自检结论

- 无待定占位或未定义缩写。
- 架构、数据流、页面结构和版本路线相互一致。
- V0.1.0 是可独立验证的纵向切片，完整 V1 范围未被删除。
- 跨模块所有权明确：任务模块拥有收入账本，冒险日志拥有投资、旅途、家园和阶段状态。
- 异常恢复、测试证据和发布门槛均可在详细实施计划中拆成可执行任务。
