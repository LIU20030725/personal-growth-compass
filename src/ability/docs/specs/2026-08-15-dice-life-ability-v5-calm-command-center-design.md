## 1. 目标与边界

V5 只重构能力模块的呈现层与直接操作体验。保留现有 Schema V2、持久化键、路由、技能树/阶段/节点/资源/成果、拖拽、依赖图、下一步、撤销重做、画布/线性路线和现有测试覆盖。

概念图只提供整体语言：冷白、鼠尾草、柔黄、清晰层级、一个主动作和低噪声工作台。不得照抄其中虚构的等级、人物、今日总览、情绪或健康模块。

北极星：**一眼知道下一步，靠近节点才出现结构操作；画布像安静的学习工作台，而不是功能展板。**

## 2. 当前页面与状态映射

### 2.1 能力首页 / 空数据

- 当前问题：创建技能树、产品说明和空态缺少明确的第一动作层级；装饰与说明会和按钮竞争。
- 首屏重点：解释“技能树用来做什么”后，唯一主动作是“新建技能树”。
- 状态：空、创建中、保存失败、创建成功后跳转。
- V5：冷白大留白、鼠尾草辅助图形、柔黄主按钮；错误就地说明并关联输入控件，不用无上下文 toast。

### 2.2 技能树工作台 / 画布

- 当前问题：技能库、视图筛选、下一步、阶段管理、画布控件和节点工具条同时高强调；常驻方形加号遮挡连线和节点；阶段框只向下增长。
- 首屏重点：当前技能树、下一步、当前路径；结构管理退入分组或上下文。
- 主动作：有候选时为“下一步 · N”；无候选时显示明确空态原因，不伪装可点击主按钮。
- V5：统一工作台工具栏；画布成为最大连续区域；缩放/定位是一组，树管理是一组；结构动作靠近对象出现。

### 2.3 技能树工作台 / 线性路线

- 当前问题：与画布共享过多桌面控件；移动端容易出现小按钮和重复入口。
- 首屏重点：当前阶段、下一节点、锁定/必修/完成语义。
- 主动作：打开或推进当前节点。
- V5：阶段分组清楚、路径连续；状态同时使用文字/图标；移动端所有主触控目标至少 44px。

### 2.4 节点详情 / 桌面检查器与移动端底部面板

- 当前问题：掌握标准、资源、成果等区块边框与按钮权重接近，难以扫读；中等宽度时画布和详情互相挤压。
- 首屏重点：节点名称、当前状态和下一可执行动作。
- 主动作：按节点状态只突出一个（开始、继续或标记掌握）。
- V5：信息按“状态 → 掌握标准 → 资源 → 成果 → 高级信息”排列；二级动作使用文字按钮或区块菜单；1024px 使用覆盖式详情而非等宽双栏；390px 为底部面板且背景不可交互。

### 2.5 资源区与资源表单

- 当前问题：空态、新增、选择已有和列表区存在重复按钮；同一层出现多个“添加”。
- 首屏重点：已关联资源；空时解释价值。
- 主动作：空态为“添加资源”，有资源时为区块标题处“添加”。
- V5：新增/选择已有在一个流程内分流；URL 错误就地显示且有 `aria-describedby`；成功后返回资源列表并将新增项置顶/聚焦。

### 2.6 阶段与技能树表单

- 当前问题：桌面尚可，但错误/成功/危险动作样式与详情区不完全一致。
- V5：保留 DialogFrame 的焦点陷阱、Escape、背景隔离和焦点恢复；危险删除有一致的产品内确认，不继续新增 `window.confirm`。

### 2.7 菜单、快捷键帮助、删除确认

- 当前问题：部分菜单只靠再次点触发器关闭；浮层阴影与边框偏重。
- V5：点击外部/Escape 关闭、焦点回触发器；菜单保持 menu/menuitem；快捷键按画布作用域解释；删除明确影响范围并提供撤销。

### 2.8 加载、错误与成功状态

- 加载：本地数据通常同步，不制造全屏 spinner；如出现延迟，保留布局骨架而非空白。
- 错误：存储失败、非法 URL、掌握证据不足、删除受阻均就地可理解显示，必要时给恢复动作。
- 成功：创建/保存后以状态变化和轻量 live region 反馈，不弹出阻塞式成功窗。

## 3. 已批准结构：平静指挥中心

### 3.1 桌面 1440px

1. 紧凑技能库横向条：当前树高辨识，其他树低强调，管理入口收束。
2. 工作台标题行：树名称/说明在左；唯一主动作“下一步 · N”在右。
3. 次级工具行：画布/路线切换、状态筛选、阶段与更多操作按功能分组。
4. 主工作区：画布占主体；详情打开后使用固定合理宽度的上下文检查器。
5. 画布控件靠边悬浮并保持一组，不与页面工具栏重复。

### 3.2 中等宽度 1024px

1. 保持工作台标题与主动作。
2. 工具行允许横向滚动或分组折叠，不换成多行按钮墙。
3. 详情以右侧覆盖抽屉呈现，画布宽度不被压到不可用。
4. 抽屉打开时焦点进入详情，关闭后回到节点。

### 3.3 移动 390px

1. 默认线性路线，不加载强交互画布为主界面。
2. 顶部保留树切换和下一步，低频动作进入菜单。
3. 节点详情为底部面板；背景不可交互，关闭后回节点。
4. 主要按钮与图标触控框至少 44×44px，无页面横向溢出。

## 4. 核心直接操作规则

### 4.1 Hover/focus 连接点创建分支

1. 未交互时，节点右侧只显示不抢眼的连接圆点。
2. 鼠标进入连接点命中区或键盘将焦点移到连接点时，圆点平滑变为加号；不在节点右上角生成独立方形按钮。
3. 点击/Space/Enter 每次创建一个直接子节点；连续三次得到三个并行直接子节点。
4. 新节点创建后进入命名并保持视口内可见。
5. 命中区至少 44×44px，可大于可见圆点，但不能覆盖节点详情点击区；按钮有可访问名称“为「节点名」添加子节点”。hover 不是唯一完成方式。
6. 不绑定 Tab 创建；画布快捷键仍受现有安全作用域约束。

### 4.2 阶段容器四向自适应

1. 节点的 `phaseId/stageId` 只由明确的结构操作改变；普通拖动永不改归属。
2. 节点拖出阶段初始矩形后，原阶段边界按全部所属节点包围盒向左、右、上、下扩张。
3. 节点拖回后，容器按相同规则收缩，但不小于空阶段最小尺寸。
4. 阶段标题区保持在容器视觉顶部；当成员向上越界时，整体容器上移并保留标题安全区。
5. 所有坐标与尺寸为有限值并吸附到 16px 网格；阶段内边距、标题区、节点工具条和分支母线纳入包围盒安全距离。
6. 自动布局清除手工偏移并恢复标准列/行对齐；手工布局重载后保持。

## 5. 视觉 Token 与组件规则

### 5.1 Token

- `--ability-canvas: #F7FAF8`: 冷白主画布。
- `--ability-surface: #FFFFFF`、`--ability-surface-subtle: #F1F7F4`: 主/次工作面。
- `--ability-sage: #6F9587`、`--ability-sage-soft: #D9ECE5`: 阶段、完成、辅助图标和次级动作。
- `--ability-yellow: #F2D66B`: 当前节点、下一步和唯一主 CTA；禁止同屏多处高强度黄色。
- `--ability-text: #26332F`、`--ability-text-muted: #60706A`。
- `--ability-border: #DDE8E2`: 低对比 1px。
- 圆角：控件 10–12px、节点/卡片 14–16px、弹层 16px。
- 阴影：仅浮层、抽屉、菜单；节点和阶段默认不用硬阴影。

### 5.2 去噪

- 删除粗黑边、双重描边、硬投影和装饰性胶囊；正文不小于 14px，辅助文字原则上不小于 12px。
- 工具栏只按任务分组，不为每个动作创建独立卡片。
- 图标按钮有 tooltip/可访问名称；文本按钮用于不熟悉的业务动作。
- 同屏每个区块最多一个显著主动作。

## 6. 可访问性与输入方式

- 不改变 React Flow 的 application 语义；同步线性路线继续提供读屏与键盘路径。
- 所有 icon-only 控件有名称；状态、锁定、必修、进度不只靠颜色。
- 连接点加号支持 hover、focus-visible、Enter 与 Space。
- 菜单支持 Escape、方向键/Tab、点击外部与焦点回归。
- Dialog/Drawer 进入时设置初始焦点、约束焦点、关闭后恢复，并隔离背景。
- 200% 缩放不遮挡主操作；390px 触控目标 ≥44px。

## 7. 不做事项

- 不升级 Ability Schema，不改变已有本地数据键和路由。
- 不增加依赖、AI、外部采集、浏览器扩展或云端资源库。
- 不把阶段误拖变成结构迁移。
- 不删除画布、路线、资源、成果、拖拽、缩放、撤销等现有能力。
- 不照搬概念图的角色、等级和跨模块总览。

## 8. 验收标准

1. 节点常态无方形加号；只有连接圆点 hover/focus 时显示加号并能逐个创建并行子节点。
2. 节点跨越阶段视觉边界后归属不变，原阶段四向扩缩包住全部成员；回拖后正确收缩。
3. 1440px 画布与详情层级清楚；1024px 不再挤成不可用双栏；390px 使用线性路线和底部详情。
4. 每页/每区只有一个主动作，所有旧功能仍可达。
5. 低对比 1px 边框、12–16px 圆角、克制阴影和柔黄强调一致。
6. 单元/组件/全仓测试、生产构建、Playwright、axe 与控制台门禁全部通过。
