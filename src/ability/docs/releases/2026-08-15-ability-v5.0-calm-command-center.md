## 本次变更

1. 采用 A 方案“平静指挥中心”：冷白画布、鼠尾草层级、柔黄仅用于主操作和当前状态；统一 1px 低对比边框、12–16px 圆角和柔和阴影，移除粗黑框、硬阴影与过量胶囊。
2. 把节点永久 `＋` 改为飞书式连接端口：静止仅显示圆点，hover 或键盘 focus 时展开加号；点击或 Enter/Space 每次只创建一个直接子节点。
3. 阶段容器根据所属节点的四向边界自动扩张和回缩。节点拖进其他阶段视觉区域仍属于原阶段，不通过误拖改变学习结构。
4. 修复父节点被拖到子节点右侧时的正交路径，反向线路仍从统一母线回到目标节点边缘；三、五、多层分支视觉门禁保持通过。
5. 收敛操作层级：当前技能区只突出“下一步”主 CTA，结构创建回到阶段和节点端口，画布工具栏聚焦视图与历史操作，详情与资源采用渐进展开。
6. 1024px 详情改为覆盖层，避免压缩画布；390px 保持线性路线与底部详情，并在详情打开时隔离整页背景、关闭后恢复原节点焦点。
7. 统一关键操作的 44px 命中区域，并修复低对比标签，axe critical/serious 归零。

## 数据与迁移兼容

- Ability 领域 Schema 保持 V2，未新增破坏性迁移。
- `dice-life.ability.v1`、`dice-life.ability-canvas.v1` 的数据键、资源、成果、依赖、并行组、阶段归属和手工坐标语义保持不变。
- 阶段自动扩缩仅是画布布局推导；不会写回节点 `phaseId`，也不会删除旧任务关联或掌握说明。
- 没有新增 npm 依赖、路由或外部数据上传。

## 已知限制

1. 手机端仍以线性路线为主要交互，不提供复杂自由画布拖拽。
2. 极端远距离拖动会扩大原阶段框；可用“重新自动布局”恢复。
3. 跨阶段调整必须显式编辑节点阶段，不支持通过几何拖入自动迁移。
4. Refero 因当前账户 `NO_SUBSCRIPTION` 未提供可验证 ID；未伪造或声称使用不可访问的参考。
