## 本次变更

1. 移除“编辑技能树”页面模式，阶段、节点、子节点、详情、重命名、拖动与结构操作改为画布常驻的直接操作；新树可连续添加阶段、根节点和多个并行子节点。
2. 阶段成为可拖动画布节点，并以弱于技能依赖线的中性虚线表达顺序；阶段拖动会带动成员节点，支持 16px 吸附、刷新持久化、重新自动布局、撤销和重做。
3. 节点单击直接打开详情，关闭按钮只关闭面板并保留画布选择上下文，点击画布空白清除选择并关闭详情；修复 React Flow 陈旧 selection 导致详情被重新打开的竞态。
4. “下一步”常驻显示可行动候选数，连续点击会稳定轮换并行候选并聚焦打开详情；空树、全部掌握和前置阻塞分别提供原因。
5. 成果从当前节点详情发起并固定归属于该节点，不再提供可误选的节点下拉框；树上成果继续通过节点关联呈现。
6. 快捷键限定在画布聚焦且存在选择时生效，保留 Tab 原生导航；快捷键说明弹窗支持焦点约束、Esc 关闭和焦点恢复。
7. 视觉继续沿用硬朗编辑器风格、中性底色和单一黄色主强调；收紧顶栏动作、Next 数量、阶段拖动光标、常驻加号位置、线性视图新增/撤销按钮、快捷键弹窗与 390px 触控目标。

## 数据迁移与兼容

- Ability 领域数据继续使用 schema V2；未升级 `schemaVersion`，V1 → V2 的既有无损迁移路径保持不变。
- 能力数据仍写入 `dice-life.ability.v1`，旧技能树、阶段、节点、依赖、并行组、成果、资源、旧任务关联和 masteryNote 的兼容语义不变。
- 画布偏好仍写入 `dice-life.ability-canvas.v1`。`CanvasPreferences.phasePositions` 为向后兼容的可选扩展：旧记录缺失时读取为空对象；保存后与节点 `positions`、折叠状态和 viewport 共存。
- 重新自动布局只清空当前树的节点与阶段手工坐标；Ability schema 与领域内容不受影响。

## 已知限制与待验收项

1. 本归档记录的是开发自检，不代表最终验收通过；正式视觉 baseline、跨浏览器矩阵、人工键盘走查和总控独立场景仍等待测试方案。
2. 移动端默认提供线性路线，复杂画布拖动仍主要面向桌面；线性视图提供添加、详情、撤销和重做替代路径。
3. 阶段顺序线表达流程顺序，不参与技能前置条件计算；技能依赖线仍是唯一的节点可行动约束。
4. 阶段与节点拖动采用网格吸附和 localStorage 偏好，不支持多人协同坐标合并或跨设备同步。
5. 资源、AI 推荐和自动拆树的 V3 已知限制继续存在，V4 未扩展这些领域能力。
