## 结论

用户关于“V5 看起来没有明显优化”的反馈成立。原 V5 虽已统一冷白、鼠尾草和柔黄，但桌面首屏仍连续堆叠页面介绍、技能库、当前技能摘要和画布工具，属于 Severity 3 的信息架构问题，而不是颜色问题。

V5.1 将有当前技能树时的页面重构为一个任务导向指挥栏：当前技能名称成为唯一 H1，进度、当前阶段和“下一步”同处首屏；技能库压成一行；低频画布工具收进可发现菜单。使用同一套 3 阶段、12 节点真实数据进行自动量化：

- `origin/main`：1440×900 首屏技能节点数为 0；画布顶部在 800px 以下，用户必须滚动后才看见技能树。
- V5.1：1440×900 首屏可见技能节点不少于 12；画布顶部不高于 450px，首屏同时看见当前任务、技能库和技能树全貌。
- 页面主标题由泛化的“能力技能树”改为当前技能“个人品牌内容增长系统”，减少一次上下文辨认。

这些数字由 `ability-v5-visual-reality.visual.ts` 直接断言，截图不能用弱数据或裁切页面中段代替。

## 前后结构对照

| 维度 | origin/main | V5.1 | 用户影响 |
| --- | --- | --- | --- |
| 首屏层级 | 页面介绍 → 技能库 → 当前技能摘要 → 筛选 → 画布 | 当前技能指挥栏 → 单行技能库 → 轻量筛选 → 画布 | 当前目标与下一步先出现，技能树不再落到首屏以下 |
| 页面主标题 | 泛化模块名 | 当前技能树名称 | 无需再次确认正在编辑哪棵树 |
| 主动作 | 新建技能树、修改、添加阶段、下一步等多处争抢 | 柔黄只突出“下一步” | 每页只有一个明显主动作 |
| 画布工具 | 添加阶段、添加节点、自动布局、定位、撤销、重做、快捷键七项同层 | 添加节点、定位、撤销、重做 + “工具”菜单 | 高频操作保留；添加阶段、自动布局、快捷键渐进展开 |
| 技能库 | 独立大区块 | 搜索、当前技能卡、查看全部、新建一行排列 | 保留无限技能树能力，同时减少纵向占用 |
| 连接分支 | 永久或显眼入口易误触 | 静止为连接圆点，hover/focus 才显示 `＋` | 与飞书思维导图一致，一次激活创建一个直接子节点 |
| 阶段归属 | 视觉越界可能造成误解 | 原阶段框随所属节点扩缩，跨框不改归属 | 误拖不改变学习结构，自动布局可恢复 |
| 390px | 画布不适合作为主要入口 | 默认线性路线，详情为底部层并隔离背景 | 关键任务可单手完成，不把桌面画布硬塞进手机 |

## 关键任务步数

| 任务 | 操作 | V5.1 结果 |
| --- | --- | --- |
| 找到当前最优先节点 | 点击一次“下一步” | 自动定位、居中并打开详情；并行候选显示数量并稳定轮换 |
| 创建一个分支 | 移到/聚焦连接圆点 → 激活一次 | 创建一个直接子节点；连续激活产生并行兄弟节点 |
| 添加普通节点 | 点击一次“添加技能节点” → 填写并保存 | 高频入口保持在画布工具栏首位 |
| 添加阶段 | 点击“添加阶段” → 填写并保存 | 指挥栏保留直接入口；画布工具菜单也保留同义入口 |
| 自动恢复布局 | 打开“工具” → “重新自动布局” | 两步完成；低频操作不再与日常动作争抢视觉权重 |
| 查看节点资料 | 单击节点 | 详情打开；资源、掌握标准、成果在节点内部渐进显示 |
| 关联学习资源 | 单击节点 → “收藏” → 保存/选择已有 | 资源不污染画布，可跨节点复用并安全解除关联 |
| 移动节点越过阶段框 | 一次拖动 | 原阶段框自动扩张包住节点；归属 ID 不变；撤销后恢复 |
| 手机查看与推进 | 单击线性节点 | 底部详情打开；关闭后焦点回到原节点 |

| 2. 单一主动作 | 多个黄色/高对比操作同层 | 3 | 柔黄仅用于“下一步”和当前状态 |

| 15. 性能与稳定性 | 新结构不得改变 Schema 或引入依赖 | 1 | Schema V2、路由和持久化键不变；无新增依赖；200 节点流程通过 |

### 已保留的优点

1. 画布仍是桌面端核心辨识特征，三/五/多层分支的正交几何和阶段容器没有被“卡片墙”替代。
2. 节点详情继续把掌握标准、学习资源和真实成果放在同一技能上下文中，画布保持干净。
3. “下一步”已有候选轮换、定位、详情打开和跨视图同步能力，本轮将其提升为产品核心动作，而非重新发明流程。
4. 移动端线性路线、焦点回归、背景 inert、44px 触控目标继续保留。

## 已知限制与接受理由

1. 1440px 的“全树概览”会缩小节点文字；这是首屏展示整体结构与保持画布辨识度的取舍。“下一步”和“定位”会放大到当前节点，滚轮/控件可继续缩放。
2. 1024px 打开详情时详情覆盖画布右侧，避免把画布再次压窄；关闭后完整工作区恢复。
3. 390px 不提供复杂自由画布拖拽，默认线性路线。这是移动端可操作性边界，不是功能删除。
4. 节点拖得极远会使原阶段框显著扩大；“重新自动布局”可恢复。跨阶段归属仍需显式编辑，避免误拖改变学习结构。
