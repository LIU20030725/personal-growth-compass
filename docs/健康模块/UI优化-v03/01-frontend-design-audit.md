# 健康模块 UI/UX 审计（v03 重设计前）

日期：2026-08-15
分支：`codex/health-ui-v03`（基线 `origin/main@e82e31b`）

## 审计范围

- 生产界面：健康首页、身体状态、饮食记录、日常健康、运动健身、数据与隐私。
- 隐藏与动态状态：空态、错误提示、照片读取、进阶训练字段、休息计时、草稿恢复、导入预检、垃圾箱、永久删除确认。
- 响应式：1440×900、1024×768、390×844 的既有验收截图与当前本地页面。
- 源码：`src/health/HealthModule.tsx`、`src/health/healthModule.css`、`src/App.tsx`、`src/styles.css`，以及健康模块组件/可访问性测试。
- 方法：逐项覆盖 15 条可用性原则，严重度 0–4。技能引用的扩展 `heuristics.md` 在本机不存在，因此本报告依据技能正文给出的 15 条定义与检查清单执行，并明确保留这一限制。

## 结论

当前版本已经具备完整、谨慎的数据能力，但信息架构仍是“把四个子系统和它们的表单展示出来”，而不是“帮助用户完成今天最常做的记录”。主要问题不是配色，而是首屏优先级、任务流和记录时的上下文。

## 最优先修复

1. 将首页从“四入口并列”重构为“今日概览 → 一键记录 → 最近训练/身体趋势 → 历史与数据管理”。
2. 将训练改为有明确开始、进行中和结束状态的任务流，动作库和高级字段渐进披露。
3. 用站内抽屉/弹层替代 `window.prompt` 与 `window.confirm`，补齐焦点、取消、错误恢复。
4. 将导入从粘贴 JSON 改为文件选择、预检摘要、确认整体替换的三步流程。
5. 移动端采用短首屏、底部主要动作和局部展开，避免连续长表单。

## Severity 3 — 重大问题

### 3.1 四个子系统在首屏平权，用户没有明确下一步

- **原则：** 结构、可感知性、识别优于记忆、美学与极简。
- **位置：** `HealthModule.tsx:130-178`；`healthModule.css:75-109`。
- **问题：** 今日卡片、四张等权入口卡、趋势卡和数据链接依次堆叠。四张卡形状、尺寸、视觉重量一致；“快速记录”实际上只进入日常健康。
- **用户影响：** 用户想记录体重、餐食或训练时仍需先判断该走哪个子系统；“快速记录”与实际能力不一致，首次点击会降低信任。
- **修复：** 首页只保留一个明确的“一键记录”入口，打开可识别的记录动作面板；把四子系统降为今日摘要与最近活动中的上下文入口，数据管理沉到次级导航。

### 3.2 子页面以数据库分区和表单为中心，不以用户任务为中心

- **原则：** 结构、现实映射、效率、美学与极简。
- **位置：** `HealthModule.tsx:182-300,302-416,418-596,598-777`；`healthModule.css:113-146`。
- **问题：** 桌面端统一套用“左侧新增表单 + 右侧历史”的双栏模板。身体、饮食、日常和训练虽然任务完全不同，却被压成同一布局。
- **用户影响：** 高频记录和低频设置拥有相同视觉权重；用户每次进入都要重新扫描整张表单，难以形成肌肉记忆。
- **修复：** 身体与饮食使用轻量记录抽屉；日常指标使用可直接点击的快捷动作；训练使用专门的进行中页面；历史和设置只在需要时展开。

### 3.3 训练没有“开始—进行—结束”的清晰状态

- **原则：** 系统状态可见、现实映射、效率、结构。
- **位置：** `HealthModule.tsx:598-776,957-1306`。
- **问题：** 创建项目、项目列表、计时器、草稿、逐组表单和历史记录全部在同一面板内。选择动作后没有显著的当前动作标题、训练总时长、已完成动作进度和结束训练动作。
- **用户影响：** 训练中用户需要在大量静态内容里寻找当前组；休息计时与本组填写分离，误操作和漏记概率高。
- **修复：** 建立训练准备页、进行中页、结束摘要三态；进行中首屏固定训练计时、当前动作、上一组参考、本组输入和休息按钮；动作库作为底部抽屉。

### 3.4 原生浏览器提示框破坏上下文与可访问性

- **原则：** 用户控制与自由、错误预防、错误恢复、无障碍。
- **位置：** `HealthModule.tsx:272-291,705-717,820-829,914-927`。
- **问题：** 更正、归档、整体替换和永久删除依赖 `window.prompt` / `window.confirm`，无法提供字段级校验、影响摘要、稳定焦点或一致视觉反馈。
- **用户影响：** 键盘与辅助技术用户难以理解上下文；用户取消或输入错误后没有恢复路径；重要操作的风险表达不一致。
- **修复：** 使用站内对话框/抽屉，包含标题、影响说明、明确主次按钮、Esc、焦点约束与返回焦点；更正使用正常表单并展示原值。

### 3.5 移动端只是把桌面内容纵向堆叠

- **原则：** 结构、效率、可感知性、可点击性。
- **位置：** `healthModule.css:294-330`。
- **问题：** 390px 下四张入口卡变为四个 128px 高的单列卡片，双栏变单栏，训练和日常表单完整向下延伸；没有底部主要动作或分段导航。
- **用户影响：** 首屏只能看到标题、今日卡和一部分入口，常用动作需要长距离滚动；训练中单手操作成本高。
- **修复：** 移动端首页用横向摘要/短列表；主要记录动作固定在拇指区；训练进行中使用单列组编辑和粘性底栏；设置与历史折叠。

### 3.6 导入要求用户粘贴原始 JSON

- **原则：** 现实映射、错误预防、帮助、宽容性。
- **位置：** `HealthModule.tsx:780-831`。
- **问题：** 用户需要打开备份文件、复制全部内容并粘贴到文本域，之后才看到预检。
- **用户影响：** 非技术用户很难完成；超长内容易截断或误选，错误成本高。
- **修复：** 使用 `.json` 文件选择器，读取后展示文件名、日期、记录数、媒体数和校验状态；确认后整体替换，失败保持原数据。

## Severity 2 — 次要问题

### 2.1 “今日”统计混用了全量历史

- **原则：** 系统状态可见、容错。
- **位置：** `HealthModule.tsx:132-142,569,775`。
- **问题：** 首页“今日状态”展示 `health.meals.length` 和 `health.workouts.length`，日常页“今天已有”使用 `health.daily.length`，训练页完成次数也无时间范围。
- **用户影响：** 有历史数据后数字与“今日”语义不符，用户会误判当天是否记录过。
- **修复：** 所有“今日”指标按本地日界过滤；全量历史明确标为“累计”。

### 2.2 趋势只有一段文字，没有时间范围与可核对记录

- **原则：** 可感知性、系统状态可见、帮助。
- **位置：** `HealthModule.tsx:165-176,251-297`。
- **问题：** 首页趋势只给 7/30 天计数；身体趋势只显示 30 天文本，缺少 7/30/90 切换、记录点和文字等价表。
- **用户影响：** 用户无法快速判断变化发生在何时，也不能从结论追溯到原始记录。
- **修复：** 提供 7/30/90 分段控制、迷你趋势与最近记录表；覆盖不足时只显示记录点，不做比较。

### 2.3 BMI 反馈滞后且与当前输入脱节

- **原则：** 系统状态可见、现实映射。
- **位置：** `HealthModule.tsx:237-247`。
- **问题：** BMI 字段展示最近一条已保存记录，不根据当前身高体重预览。
- **用户影响：** 用户修改输入时会看到旧 BMI，容易误以为系统计算错误。
- **修复：** 当前表单实时显示预览值，并明确“保存后写入本次记录”；无有效输入时保持中性空态。

### 2.4 餐食缺少编辑入口与明确时间控制

- **原则：** 用户控制与自由、宽容性。
- **位置：** `HealthModule.tsx:302-416`。
- **问题：** 保存后只能删除，不能直接更正；餐食时间固定由系统生成。
- **用户影响：** 补录昨日餐食或修改文字时必须删除重建。
- **修复：** 记录抽屉允许选择时间；时间线条目提供编辑和删除，编辑复用同一表单。

### 2.5 指标管理与高频记录平分页面

- **原则：** 结构、美学与极简。
- **位置：** `HealthModule.tsx:571-595`；`healthModule.css:113-122`。
- **问题：** 低频的启用指标设置占据日常页一整列。
- **用户影响：** 每次喝水或记睡眠都要看到重复设置，增加视觉负担。
- **修复：** 设置移动到“管理指标”抽屉；主页面仅显示已启用指标的今日状态与快捷动作。

### 2.6 删除、编辑、归档等动作视觉层级相近

- **原则：** 错误预防、可点击性、可感知性。
- **位置：** `healthModule.css:155-162`；`HealthModule.tsx:699-717,835-877`。
- **问题：** 普通、次要和破坏性按钮使用相近的描边样式。
- **用户影响：** 快速操作时难以区分“记录”“归档”“永久删除”。
- **修复：** 建立主按钮、次按钮、文本按钮、破坏性按钮四级；破坏性只在确认场景出现，不用红色健康警报语义。

### 2.7 照片只有“读取中”，没有失败与重试状态

- **原则：** 错误恢复、系统状态可见。
- **位置：** `HealthModule.tsx:929-955`。
- **问题：** 媒体不存在或读取失败时占位会永久停留在“照片读取中”。
- **用户影响：** 用户无法判断是仍在加载还是数据损坏，也没有重试动作。
- **修复：** 增加加载、成功、失败三态；失败提供重试与从记录移除引用的安全路径。

### 2.8 进阶字段折叠正确，但普通组记录仍缺少上次值和复制捷径

- **原则：** 效率、识别优于记忆。
- **位置：** `HealthModule.tsx:1030-1045,1139-1235`。
- **问题：** 用户可复制整次训练，却不能在当前动作旁直接看到并复制上一组/上次同动作数据。
- **用户影响：** 训练中要记忆重量与次数，降低单组更新速度。
- **修复：** 当前组旁显示上次同动作记录；提供“复制上一组”，复制后字段仍为独立值。

## Severity 1 — 表层问题

### 1.1 所有内容都使用同一种白色圆角卡片

- **原则：** 美学与极简、结构。
- **位置：** `healthModule.css:40-48`。
- **问题：** 今日摘要、入口、表单、历史都使用边框、圆角和阴影，层级靠重复卡片而非空间和排版表达。
- **修复：** 只让可操作的独立对象使用卡片；趋势、历史与说明改用分区背景、分隔线和留白。

### 1.2 英文眉题与 Dice Life 其他模块语气割裂

- **原则：** 一致性与标准、现实映射。
- **位置：** `HealthModule.tsx:115-117`。
- **问题：** `HEALTH JOURNAL` 在中文任务流中没有信息价值。
- **修复：** 改为中文上下文标签或移除，把视觉识别交给模块图标与版式。

### 1.3 视觉反馈与交互状态偏弱

- **原则：** 可点击性、可感知性。
- **位置：** `healthModule.css:28-39,66-103,147-162`。
- **问题：** 主要按钮、入口卡缺少统一 hover/pressed/disabled 反馈，当前子页面只依靠标题判断。
- **修复：** 建立统一的 hover、pressed、focus-visible、disabled 和选中态；状态不能只靠颜色。

## 15 条原则覆盖矩阵

| 原则 | 结论 |
|---|---|
| 1. 系统状态可见 | 今日统计语义错误；训练进行状态弱；已有 `aria-live` 是优点。 |
| 2. 现实映射 | 训练未映射真实训练流程；JSON 导入偏技术化。 |
| 3. 用户控制与自由 | 原生确认框和餐食不可编辑限制控制；垃圾箱恢复是优点。 |
| 4. 一致性与标准 | 四子页视觉一致，但一致得过度；英文眉题与其他模块语气不一致。 |
| 5. 错误预防 | 导入预检、永久删除二次确认是优点；原生确认缺少影响摘要。 |
| 6. 识别优于记忆 | 首页四入口可识别；训练缺少上次值与当前上下文。 |
| 7. 灵活性与效率 | 饮水快捷量和复制上次训练是优点；长表单与缺少复制上一组拖慢操作。 |
| 8. 美学与极简 | 低焦虑配色正确；卡片化过度、设置与主任务同权。 |
| 9. 错误恢复 | 全局错误横幅、垃圾箱与导入回滚是优点；照片失败无恢复。 |
| 10. 帮助与文档 | 非医疗边界、空态说明清楚；导入和训练缺少就地指引。 |
| 11. 可点击性与示能 | 多数按钮达到 44px；动作层级和交互状态不足。 |
| 12. 结构 | 首屏与子页按系统模块组织，而非按今日任务组织。 |
| 13. 无障碍 | 语义表单、标签、减弱动效和 axe 基线良好；原生弹窗、动态焦点与复杂训练流仍需改善。 |
| 14. 可感知性 | 字体和对比度总体清楚；趋势、当前训练、主次动作缺少视觉重点。 |
| 15. 宽容性 | 缺失不等于 0、软删除、本地草稿是优点；餐食时间/编辑与导入输入不够宽容。 |

## 至少保留的优点

1. **低焦虑、非医疗边界清楚：** 缺失不等于失败，不用红色健康警报，不输出诊断或风险结论。
2. **本地优先与恢复能力扎实：** 照片本地存储、导出校验、导入回滚、软删除和垃圾箱恢复已经形成可信的数据底座。
3. **进阶训练字段采用渐进披露：** 分段、组类型、侧别、额外/辅助重量默认折叠，不增加普通记录负担。
4. **基础无障碍意识良好：** 有跳转主内容、语义标题、输入标签、`aria-live`、44px 触控目标和 `prefers-reduced-motion`。
5. **功能完整度高：** 身体、餐食、日常、五种训练模式和完整备份能力均已具备，重设计无需重写业务数据层。

## 审计后的设计约束

- 首页不再把四个子系统当作四张等权卡片。
- 任何“快速记录”必须能直接选择身体、饮食、日常或训练，而不是只进入饮水页。
- 高频记录始终先于设置、历史和数据管理。
- 不增加医疗化指标、综合健康分或红色警报。
- 保留本地优先、缺失为空、可更正、可恢复与完整导入预检。
- 训练高级能力继续渐进披露，不增加第六种记录模式。
