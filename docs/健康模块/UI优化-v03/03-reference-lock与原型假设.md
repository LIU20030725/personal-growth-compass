# 健康模块 v03 Reference Lock 与原型假设

日期：2026-08-15

## 主风格

**主风格：Dice Life 冷白记录台。**

界面像一张安静、可随手补写的个人记录台，而不是医疗仪表盘。冷白为大画布，鼠尾草承担导航、结构与选择状态，柔黄只承担当下最主要动作。数据数字清楚、克制、可核对；不使用综合健康分、警报红、炫光渐变或虚假的精准健康结论。

## 借用细节

仅从用户提供的 OtterLife 截图借用两类结构规律：

1. **任务模式优先：** 训练页按热身—训练动作—拉伸组织，进行中计时与当前动作始终可见。
2. **动作面板优先：** 一个“一键记录”打开带文字标签的动作面板；动作库/食物记录/身体记录使用抽屉或局部展开，不把所有表单铺在主页面。

## 信息层级

1. 今日概览：今天真实发生了什么、最后一次记录是什么。
2. 一键快速记录：饮水、睡眠、餐食、身体、训练五个可识别动作。
3. 继续任务：恢复训练草稿、继续最近项目、复制上次训练。
4. 趋势与历史：身体 7/30/90 天变化、最近训练和最近餐食。
5. 管理：指标开关、训练项目、导入导出、垃圾箱、隐私说明。

首页不再出现四个等权模块卡。四类数据仍完整存在，但只在今日摘要、快速记录面板和次级导航中按上下文出现。

## 交互规则

- 一次只突出一个主要动作；同一区域最多一个柔黄实心按钮。
- 快速记录面板先选记录类型，再展示最少字段；保存后返回原上下文并用 `aria-live` 宣告。
- 桌面使用右侧抽屉，移动端使用底部 sheet；二者共用语义、字段和焦点规则。
- 训练从准备页进入进行中页，再到结束摘要；休息计时属于当前动作，不在页面其他位置重复。
- 设置、导入导出和垃圾箱不占首页首屏。
- 趋势覆盖不足时展示记录点与空态，不强行比较；每条复盘都可回到依据记录。
- 编辑、更正、归档和删除全部使用站内表单或确认对话框，支持 Esc、取消和返回焦点。

## 视觉规则

- 画布：冷白，不使用纯白卡片铺满整页。
- 结构色：鼠尾草用于导航、分隔、选中和次级按钮。
- 动作色：柔黄仅用于当前主要动作和重点数字的轻背景。
- 文字：深墨绿黑；次级文字仍满足 4.5:1。
- 卡片：只用于可独立操作或可浏览的对象；趋势、说明、历史优先用分区和分隔线。
- 数字：启用 tabular figures；今日核心数字建立明显层级。
- 圆角：外层 18–22px，内部控件 10–14px，不让所有元素都成为药丸。
- 动效：150–220ms，主要使用 opacity/transform；遵守 reduced motion。

## 明确禁用

- 四张等宽入口卡抢首屏。
- 紫蓝 AI 渐变、霓虹悬浮按钮、装饰性玻璃拟态。
- 红色健康警报、综合健康分、疾病风险、诊断、治疗或处方语气。
- 无依据的卡路里、代谢、宏量营养素、心率、血氧、睡眠阶段。
- 大面积人体插画阻挡记录；围度图只能作为身体趋势的辅助导航。
- 需要用户粘贴 JSON 的导入主流程。
- 为了“高级”而增加新依赖、重写数据层或引入外部上传。

## 三套原型假设

### A — 今日行动流（推荐假设）

首屏是一条纵向任务流：今日摘要 → 一键记录 → 继续训练/最近记录 → 两个紧凑趋势 → 管理入口。桌面主列 + 右侧窄趋势栏，移动端自然合并为单列。

- 优点：最贴合高频记录；首次用户和已有数据用户都能快速找到下一步。
- 风险：四类数据的“模块感”变弱，需要通过快速记录面板和次级导航保持可发现性。

### B — 日历时间线

首屏以日期条和当天时间线为主，饮水、餐食、身体和训练混合呈现；顶部加号补录，趋势从时间线卡片进入。

- 优点：真实、可复盘；适合补录和查看一天发生了什么。
- 风险：新用户空态较弱；训练进行态不适合嵌在时间线里。

### C — 模式工作台

顶部保留身体/饮食/日常/训练四个分段模式，默认“今日”，每个模式拥有 OtterLife 式专用页面和浮动记录动作。

- 优点：子系统能力最容易被发现；每类页面可以高度定制。
- 风险：仍要求用户先理解分类；桌面端容易回到四套产品拼在一起的问题。

## 原型比较标准

- 首条常用记录可见点击数。
- 首屏是否只有一个主要动作。
- 训练草稿能否一眼恢复。
- 390px 下是否无需长滚动即可开始记录。
- 空态与有数据态是否都成立。
- 键盘顺序、焦点可见性和屏幕阅读语义是否自然。
- 是否保留现有真实数据密度而不伪造硬件数据。

## 原型实测与选型

三套原型均在真实 Dice Life 外壳内运行，使用现有健康状态的真实计数和空态；通过 `?variant=A/B/C` 切换，仅用于结构比较，不执行保存。

| 方案 | 1440 页面高度 | 390 页面高度 | 横向溢出 | 高频记录入口 | 结论 |
|---|---:|---:|---|---|---|
| A 今日行动流 | 1156px | 1566px | 无 | 首屏直接显示 5 种动作 | **采用** |
| B 日历时间线 | 964px | 1318px | 无 | 首屏时间线与补记并存 | 不采用完整结构，仅借用“最近记录按时间排列” |
| C 模式工作台 | 1235px | 1690px | 无 | 需要先理解模式或点击浮动加号 | 不采用 |

### 自主选择：A 今日行动流

选择 A 的原因：

1. 与总控确定的“今日概览 → 一键快速记录 → 训练/身体趋势 → 历史与数据管理”顺序完全一致。
2. 五种常用记录在首屏直接可识别，不要求用户先理解身体/饮食/日常/训练四个系统分类。
3. 训练草稿和身体趋势都能进入首屏第二层，兼顾“继续做”和“回头看”。
4. 桌面可使用主列 + 趋势窄栏，移动端可自然合并，不依赖固定时间点或宽表格。
5. 能保留缺失为空、本地优先和非医疗边界，不需要伪造日程、卡路里或硬件指标。

### 拒绝 B 的原因

- 视觉上最紧凑，但固定 07:40、09:10、12:30、18:30 会把“记录事实”误导成“按计划完成”。
- 空态被包装成完整时间线，容易让用户把缺失理解为待办。
- 采用其优点：在首页下半部用真实时间排序“最近记录”，不制造计划时间。

### 拒绝 C 的原因

- 顶部五模式让用户再次先分类后操作，回到四子系统抢注意力的问题。
- 身体、饮食、训练卡仍然是等权入口；移动端页面最长。
- 浮动加号缺少动作文本时发现性弱。

### 原型发现的共享问题

- 390px 下全局顶部导航会压缩文字。生产改造将对健康场景提供可读的移动头部处理，并补全共享导航回归证据。
- 原型 A 的横向快速动作在移动端只露出前两项；生产版改为可见的 2×3 动作网格或带明确滚动提示的布局，确保身体与训练无需猜测即可发现。

原型截图保存在 `prototype-screens/`。选型完成后，`?variant` 切换器与 A/B/C 临时代码必须删除；只有上述结论和截图保留。
