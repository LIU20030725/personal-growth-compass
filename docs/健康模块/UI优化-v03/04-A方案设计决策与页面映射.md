# 健康模块 v03：A 方案设计决策与页面映射

日期：2026-08-15
状态：设计已批准，进入定向改造

## 决策

采用 A「Calm Command Center / 平静指挥中心」。参考概念图只锁定视觉语言和信息层级，不照搬其中的等级、情绪、能力、计划或虚构统计。健康模块继续使用现有真实数据、领域模型、持久化、路由与非医疗边界。

核心路径固定为：

> 今日概览 → 一键快速记录 → 继续训练 / 身体趋势 → 历史与数据管理

首页只有“一键记录”一个柔黄主动作。身体、饮食、日常和训练作为紧凑入口与快速记录选项保留，不再以四张等权大卡争夺首屏。

## 参考图适配规则

- 冷白作为连续画布，鼠尾草承担导航、边界、图标与选中态；柔黄只用于当前主动作或当前状态。
- 使用 1px 低对比边框、12–16px 圆角和柔和阴影；取消粗黑框、硬阴影以及无意义的胶囊标签。
- 数字使用等宽数字特性，缺失显示“尚未记录”，不自动补成 0。
- 首页状态带只呈现已有事实和记录数量，不生成综合健康分，也不把未记录解释为失败。
- 每个页面只保留一个视觉主动作；管理、修订、删除和高级字段通过分组、折叠或对话框渐进披露。
- 桌面端使用主内容与窄辅助区；平板和手机自然合并为单列，不依赖横向滚动。
- 所有主要触控目标不小于 44×44px；键盘焦点清晰；对话框支持 Esc、焦点约束和关闭后返回原触发点。
- 状态不只靠颜色表达；保存、撤销、错误和计时结束由 `aria-live` 宣告。

## 状态规范

- 空态：说明可记录什么，并提供该页主动作；不展示虚构示例数据。
- 加载态：媒体读取或导入预检期间禁用重复提交，保留原数据和明确进度文本。
- 成功态：就地确认并提供撤销或查看记录；不以庆祝动画制造健康压力。
- 错误态：说明发生了什么、原数据是否安全以及下一步；输入错误定位到字段。
- 极端值：仅提示复核，不给出正常/异常、疾病风险、治疗或处方结论。

## 全局壳适配

健康模块不重写应用路由。桌面沿用现有全局导航；390px 下优先保证模块标题、返回路径和主动作可读，导航允许换行或折叠但不遮挡内容。共享壳的任何改动都必须带财富、任务、情绪、冒险和能力模块回归证据。

## 本轮不做

- 不改变健康数据结构或导入导出协议。
- 不增加依赖、云同步、外部上传或穿戴设备连接。
- 不增加综合健康分、卡路里推算、诊断、治疗建议或 AI 处方。
- 不删除任何现有功能来换取视觉简洁。
