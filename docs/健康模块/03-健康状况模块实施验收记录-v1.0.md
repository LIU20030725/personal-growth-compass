## 已实现范围

- 健康首页渐进披露四类入口：身体状态、饮食记录、日常健康、运动健身。
- 身体状态支持身高、体重、体脂率、体脂测量方式；BMI 自动计算、不可编辑；支持历史、更正修订、软删除、恢复和基于覆盖率的中性趋势摘要。
- 饮食支持餐次、文字、本地照片、主观饱腹感；不含食物库、热量和营养诊断。
- 日常健康支持睡眠时长/可选质量、饮水、步数、可选精力；允许关闭不关心的指标。
- 运动支持距离计时、重量次数、自重次数、定时组数、时长训练；高级字段默认折叠，可记录分段、组类型、单侧、额外负重和辅助重量，并贯通编辑、复制草稿与持久化。
- 健康数据本地优先；结构化数据保存在版本化本地存储，照片保存在 IndexedDB；完整备份包含本地照片。
- V1 备份是单文件 JSON bundle，包含结构数据、媒体编码、manifest 清单与 checksum；导入完整预检并展示摘要，由用户确认后整体替换。
- V1 不做逐条合并；ZIP 与 updatedAt 分叉合并延后到 V1.1。删除可恢复；导入在媒体或结构写入失败时事务回滚，不静默覆盖当前数据。
- 所有健康提示保持事实描述与记录建议，不提供诊断、治疗、医疗风险判断或自动处方。
- 响应式布局、键盘可操作控件、减少动态效果适配，以及 serious/critical 级可访问性自动检查。

## 实施计划对齐

### V1 当前交付

1. 备份采用单文件 JSON bundle；结构数据、媒体编码、manifest 和 checksum 同包保存。
2. 导入流程固定为完整预检 → 摘要展示 → 用户确认 → 整体替换；失败事务回滚，损坏包拒绝，现有数据不被静默覆盖。
3. 五种训练模式保持不变；分段、组类型、单侧、额外负重和辅助重量作为默认折叠的进阶字段。
4. 进阶字段必须贯通新增、编辑、复制上次、草稿恢复、保存重载与摘要，不允许只存在于类型声明。

### V1.1 延后项

1. ZIP 容器与独立媒体文件目录。
2. 按实体 ID、`updatedAt` 与修订链识别分叉，并允许逐条选择本地、导入或两者保留。
3. V1 不展示或暗示上述能力已经实现。

## 总控验收重点

1. 首页是否足够轻，不让四个子系统同时制造填写压力。
2. 身体记录、餐食、饮水和训练的常用路径是否能在少量操作内完成。
3. 五种训练模式的字段是否符合真实记录习惯，多组与休息计时是否自然。
4. 趋势文案是否中性、可追溯，不把缺失数据当作零，不制造健康焦虑。
5. 导出、导入、软删除和恢复是否给用户足够的数据安全感。
6. 手机窄屏、纯键盘与减少动态效果环境下是否仍可完成核心路径。
