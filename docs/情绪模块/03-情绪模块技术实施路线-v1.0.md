# Dice Life 情绪模块技术实施路线

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在现有 Dice Life React 应用中交付一个本地优先、支持多媒体记录、内容回看与心情日历的情绪模块，同时保持现有项目外壳与数据兼容性。

**Architecture:** 采用 `src/emotion/` 功能域隔离。结构化记录存入带版本号的 localStorage，图片、视频、语音 Blob 存入 IndexedDB；所有日记流、内容库、日历和当日状态均从同一份 `EmotionEntry` 数据派生。模块内部暂用轻量视图状态完成导航，不引入全局路由与状态管理依赖。

**Tech Stack:** React 18、TypeScript 5.7、Vite 6、Vitest 2、Testing Library、原生 localStorage、IndexedDB、MediaRecorder、CSS。

---

## 1. 实施原则与范围

### 1.1 MVP 实施范围

- 同一天可创建多条情绪记录。
- 每条记录必须选择 1 个具体情绪，可选择多个活动。
- 内容支持文字、图片、视频、语音。
- 日记流、内容库、心情日历均可进入统一记录详情。
- 最新记录在当天作为“今日状态”展示，跨过本地自然日后自动失效，但历史记录保留。
- 内容默认私密，仅保存在当前设备。
- 预设情绪和活动由系统提供，首版不支持用户自定义。

### 1.2 本轮不实施

- 好友、分享、点赞、评论等社交能力。
- AI 情绪分析、心理诊断或自动建议。
- 音乐平台接入。
- 云同步、跨设备同步、账号迁移。
- 情绪统计报表和游戏化奖励。

### 1.3 工程约束

- 不改变现有全局 Header、Sidebar 和主导航机制。
- 情绪模块样式必须以 `.emotion-module` 为根作用域，避免污染其他模块。
- 不将二进制媒体转为 Base64 写入 localStorage。
- 不新增路由库和状态管理库；若未来全站引入路由，再统一迁移。
- 所有日期归属以用户本地时区计算，不能直接截取 UTC ISO 日期。

## 3. 核心数据设计

```ts
export type EmotionAttachmentKind = 'image' | 'video' | 'audio';

export interface EmotionAttachment {
  id: string;
  kind: EmotionAttachmentKind;
  fileName: string;
  mimeType: string;
  size: number;
  durationMs: number | null;
  width: number | null;
  height: number | null;
  isFavorite: boolean;
}

export interface EmotionEntry {
  id: string;
  createdAt: string;
  updatedAt: string;
  moodId: string;
  activityIds: string[];
  note: string;
  attachments: EmotionAttachment[];
  isFavorite: boolean;
}

export interface EmotionStateV1 {
  schemaVersion: 1;
  entries: EmotionEntry[];
}
```

数据规则：

- `moodId` 必填且只能指向系统预设。
- `activityIds` 去重保存，允许为空。
- `note` 去除首尾空白后最长 5000 字。
- 一条记录最多 9 张图片、1 个视频、1 段语音。
- 收藏既可作用于整条记录，也可作用于单个附件。
- Blob 使用附件 `id` 作为 IndexedDB 主键；元数据中不存临时 URL。
- 今日状态、内容库条目、日历聚合均为派生数据，不重复持久化。

## 5. 状态与错误处理标准

| 场景 | 用户反馈 | 数据策略 |
|---|---|---|
| 正在保存 | 主按钮显示“保存中”并禁用重复点击 | 不提前插入正式记录 |
| 保存成功 | 轻提示“已收好这一刻”并返回来源页 | 日记、内容库、日历同时更新 |
| 文件超限 | 在对应文件旁说明限制 | 不写入 Blob |
| 媒体写入失败 | 提示存储空间或浏览器限制 | 不写元数据 |
| 元数据写入失败 | 提示保存失败，可保留编辑内容重试 | 清理本次新增 Blob |
| 删除失败 | 提示未删除，可重试 | 保留原记录，避免产生断链 |
| 麦克风不可用 | 禁用语音入口并解释原因 | 其他输入仍可使用 |
| 数据解析失败 | 提示本地数据异常并提供恢复线索 | 备份原始字符串，加载空安全状态 |

## 6. 性能与容量策略

- 首屏只读取结构化元数据，不一次性加载全部媒体 Blob。
- 媒体进入视口或详情展开时再读取，并及时释放对象 URL。
- 日记流先渲染最近记录，记录较多后增加分页或虚拟列表。
- 月历聚合使用一次遍历生成 `dateKey -> summary` 映射，避免每个日期重复扫描全部记录。
- 保存前通过 `navigator.storage?.estimate()` 提供容量预警；该接口不可用时继续使用异常捕获兜底。
- MVP 不自动压缩原视频，产品限制通过文件大小与时长控制；图片压缩可作为发布后的性能优化。
