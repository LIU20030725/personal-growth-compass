## 1. 范围与边界

本轮只重构情绪模块的信息层级、布局、视觉层次、交互反馈、响应式与可访问性。保留现有情绪、活动、文字、图片、视频、语音、音乐、重要日、提醒、日记、内容库、日历、详情、收藏、编辑、删除、迁移、IndexedDB 媒体和 localStorage 元数据能力；不新增依赖、后端、付费能力或外部数据上传。

关键旅程：`记录此刻 → 选择情绪/活动 → 添加文字/照片/视频/语音/音乐 → 保存 → 日记/内容库/日历回看`。

### 15 项原则逐项结论

1. 系统状态：媒体识别有 loading/error；保存成功反馈不足（E-04）。
2. 现实匹配：语言温和且符合私密日记心智模型，是优点。
3. 控制与自由：弹层支持 Escape、取消和返回焦点；原生删除确认不一致（E-12）。
4. 一致性：单选语义和重复保存不一致（E-03、E-05）。
5. 错误预防：媒体校验、录音释放和删除确认完整，是优点。
6. 识别优于回忆：日历/历史路径清晰；空态和媒体识别仍可加强（E-07、E-09、E-11）。
7. 灵活与效率：音乐快捷识别和媒体按钮优秀；高频创建多一次弹层（E-06）。
8. 极简：色彩已克制，但首屏与编辑器信息密度过高（E-01、E-02、E-10）。
9. 错误恢复：音乐失败可“仅保存链接”；模块级成功/失败反馈不成体系（E-04）。
10. 帮助：低焦虑说明较好；日视图空态缺下一步（E-09）。
11. 可供性：主/次按钮可辨识；固定 dock 与重复保存争夺注意力（E-01、E-03）。
12. 结构：日记/内容库/日历信息架构稳定；导航位置和编辑器长列表需调整（E-01、E-02）。
13. 可访问性：焦点圈定、Escape、返回焦点、axe 基线表现好；若干触控目标和单选语义需修复（E-05、E-08、E-13）。
14. 可感知：情绪图形和日期状态清楚；内容库预览及首屏层级仍偏弱（E-07、E-10、E-11）。
15. 容错：草稿离开确认、录音资源清理、媒体上限与安全 URL 是明显优点。

## 4. 至少三个必须保留的优点

1. **本地优先与隐私边界清晰**：文字元数据留在 localStorage、媒体留在 IndexedDB，页面明确“仅自己可见”；符合现实匹配和容错。
2. **媒体安全与失败降级成熟**：图片/视频/语音边界、录音轨道释放、音乐解析失败后仅保存链接均已有测试；符合错误预防和恢复。
3. **弹层无障碍基础扎实**：初始焦点、Tab 圈定、Escape、关闭后返回触发按钮均已有覆盖；符合控制自由和可访问性。
4. **低焦虑文案方向正确**：不评分、不惩罚、不以连续打卡制造压力；符合真实世界和极简原则。
5. **日记—内容库—日历回看链路完整**：同一记录能从多种心智入口回到原日详情；符合识别优于回忆。

## 6. Reference lock

### 主风格

「平静指挥中心」：冷白内容画布，鼠尾草承担结构与反馈，柔黄仅用于当前状态和唯一主动作；有游戏感但不以奖励、评分或连续打卡制造压力。

### 借用细节

1. Day One 式“稳定创建入口 + 内容时间线”，创建与回看各自有清晰位置。
2. Calendar 样例的月份标题、双通道日期状态（形状/图标 + 颜色）和低密度留白。

### 布局规律

- 桌面：页头（眉题/标题/一句说明/一个主 CTA）→ 稳定次导航 → 当前状态或空态 → 历史内容。
- 移动：标题压缩；日记/内容库/日历和创建动作进入安全区底栏；主要内容不得被遮挡。
- 编辑器：一次只显示一个情绪类别和一个活动类别；已选内容跨类别保留；正文/媒体始终可到达。

### 信息层级

1. 当前任务：记录此刻。
2. 当前状态：今天是否已记录、最近一条是什么。
3. 回看入口：日记、内容库、日历。
4. 低频能力：重要日、收藏筛选、编辑/删除、音乐识别失败降级。

### 交互规则

- 每个主视图只有一个柔黄主 CTA。
- 保存只有一个按钮；按钮内显示进行中，完成后模块内 `role=status` 提示。
- 类别切换使用普通按钮 + `aria-pressed`，不伪装成未实现箭头键行为的 tabs。
- 所有可操作目标至少 44×44px；焦点环与鼠标 hover 均可见。
- 桌面直接打开高频记录；重要日继续作为次级创建动作，不抢占主 CTA。

### 禁用项

- 大面积黄色、粗黑边框、硬阴影、玻璃拟态、装饰性渐变、胶囊泛滥。
- 评分、红色惩罚、连续打卡压力、公开社交暗示。
- 删除、合并或隐藏现有媒体/重要日/收藏/回看功能。
- 将 Page Flows 或概念图的虚构数据写入生产页面。

## 8. 原型结论

总控已提供并由用户选择方案 A，视为已完成 prototype 选型。未在生产仓库创建 A/B/C 切换器，避免临时代码污染。方案 A 优于底部浮动工作台和“卡片瀑布”方案的原因：首屏任务最明确、桌面与移动的导航职责可分离、能完整保留现有功能，又最符合冷白/鼠尾草/柔黄的共享壳规范。

## 9. 已接受的限制

- Refero 无订阅，无法取得其内部 screen/style UUID；以 Page Flows 公共 URL slug 和共享设计 commit 作为可复核证据。
- 内容库真实 blob 缩略图暂不在本轮实现；它需要异步对象 URL 生命周期、缓存与大媒体性能测试，独立实施更安全。
- 自定义删除确认不是本轮必要条件；原生确认继续提供误删保护，后续若替换必须补焦点和键盘测试。
