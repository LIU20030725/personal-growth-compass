# 情绪模块音乐元数据解析服务设计 v1.4

**日期：** 2026-08-14  
**状态：** 已批准实施

## 目标

网页版用户粘贴网易云音乐或 QQ 音乐的公开歌曲链接后，自动识别歌曲名称、歌手、封面、平台和原始链接。服务只读取公开元数据，不下载、缓存或代理音频。

## 接口契约

`POST /api/music/resolve`

请求：

```json
{ "url": "https://music.163.com/song?id=1495784933" }
```

成功（200）：

```json
{
  "ok": true,
  "music": {
    "provider": "netease",
    "title": "EVERYTHING",
    "artist": "Way Ched / CHANGMO / Coogie / ASH ISLAND / BIBI",
    "coverUrl": "https://p1.music.126.net/...jpg",
    "sourceUrl": "https://music.163.com/song?id=1495784933"
  }
}
```

失败（4xx/5xx）：

```json
{ "ok": false, "error": { "code": "UNSUPPORTED_LINK", "message": "目前仅支持网易云音乐和 QQ 音乐歌曲链接" } }
```

稳定错误码：`INVALID_REQUEST`、`UNSUPPORTED_LINK`、`METADATA_NOT_FOUND`、`UPSTREAM_TIMEOUT`、`UPSTREAM_UNAVAILABLE`、`RATE_LIMITED`。

## 适配器边界

统一接口 `MusicProviderAdapter.resolve(canonicalLink, fetcher)` 返回规范化元数据。网易云与 QQ 的链接解析、固定上游地址和响应映射分别封装；前端不依赖平台响应结构。替换平台实现不改变 API 与情绪记录模型。

## 威胁边界

- 仅接受 `http/https`，且输入长度不超过 2048 字符、请求体不超过 8 KiB。
- 只允许 `music.163.com`、`y.qq.com`、`c.y.qq.com` 的公开歌曲链接；拒绝用户信息、非标准端口、IP 地址、localhost、尾点域名和其他域名。
- 不向用户提供的任意 URL发起抓取。正常链接只提取 ID，再访问代码内固定的 HTTPS 元数据端点。
- 服务端不访问用户可控的短链接或任意页面，仅从官方单曲 URL 提取 ID 后请求代码内固定上游端点；不透传 Cookie、Authorization 或用户请求头。
- 上游请求 4 秒超时、响应体最大 512 KiB；超限或格式错误按失败处理。
- 每个来源地址每分钟最多 20 次；响应不包含上游原始正文。
- 不下载、不缓存、不代理音频，不绕过登录、付费、版权或平台风控。
- 不写入密钥；平台适配器只使用公开元数据。

## 前端状态与降级

- `loading`：按钮显示“正在识别”，并通过 `aria-live` 告知进度。
- `success`：显示歌名、歌手、封面和平台，允许收藏。
- `failure`：显示具体且可行动的原因；若链接本身安全，允许“仅保存链接”。
- 网络不可用、服务未部署或平台变化时，继续使用现有分享文案解析；用户仍可保存安全原链接。

## 已知限制

- 平台公开响应不是正式稳定 SDK，字段或访问策略变化时需要替换对应适配器。
- 当前只识别单曲链接，不解析歌单、专辑、播客、搜索页或音频播放地址。
- 内存限流适合单实例和轻量 serverless；多实例生产环境应替换为共享限流存储。
- 当前固定上游由 Node `fetch` 连接，域名不可由用户改变；未实现“DNS 解析后绑定已验证 IP”的自定义 transport。若未来重新支持短链或任意跳转，必须先增加可控 DNS lookup/dispatcher，否则不得开放。
