## 1. Summary

Dice Life 情绪模块帮助用户用一个具体情绪、多个活动和可选的文字、图片、视频、语音，记录某个时刻的真实感受。所有内容会自动进入内容库，并可通过日记时间轴、内容库和心情日历回到对应的原始记录。

模块定位是“私人情绪记录与回顾空间”，不是心理诊断工具、社交平台，也不参与 Dice Life 的 XP、骰子或竞争性评分。

## 3. Background

### 3.1 项目背景

Dice Life 已包含财富、能力、健康、任务、成就和冒险日志等成长模块。现有情绪模块仍是占位状态，早期文档只规划了 1—10 分压力自评和文字记录，无法表达用户真实生活中的复杂瞬间，也无法承载照片、视频和语音等有温度的内容。

本次设计参考 Daylio 的低摩擦记录方式、微信状态的轻量状态表达，以及数字日记和 Hope Box 的内容回看机制，形成三个核心能力：

1. **记录当下：** 选择一个情绪和多个活动，补充可选内容；
2. **自动收纳：** 日记与媒体自动进入内容库，无需二次整理；
3. **按时间回看：** 通过时间轴和心情日历找到当天完整记录。

### 3.2 为什么现在做

- 情绪模块是 Dice Life 全局导航中尚未正式实现的重要模块；
- 用户已经明确了 Daylio 式记录、自动内容库和心情日历三个核心场景；
- 当前项目已有 React、TypeScript、Vitest、Testing Library 和本地存储模式，可以在不引入后端的情况下完成可验证 MVP；
- 项目已经明确“情绪是恢复系统”，低落、焦虑和压力不能被判定为失败，也不能直接产生或扣除骰子。

### 3.3 产品原则

- 不强制每天记录；
- 不给情绪贴“成功/失败”标签；
- 不把负面情绪转换成扣分、惩罚或角色退步；
- 默认完全私密；
- 先帮助表达和回看，再考虑统计洞察；
- 一次记录应在很短时间内完成，所有内容字段均为可选，只有情绪必选。

## 4. Objective

### 4.1 产品目标

建立一个低压力、可持续、能承载多媒体生活内容的情绪记录模块，让用户既能快速留下此刻，也能在未来通过日历和内容库重新理解当时的自己。

### 4.2 用户价值

- 不知道写什么时，只选一个情绪也能完成记录；
- 同一天可记录多次，不必把一天压缩成单一心情；
- 图片、视频和语音与情绪、活动、时间保持在同一上下文；
- 不需要手动整理，内容会自动进入内容库；
- 日历展示每天最后一次状态，同时保留当天全部变化；
- 用户的隐私记录不进入公开动态，也不会被用来计算成长排名。

### 4.3 验证型 Key Results

这些目标用于 MVP 可用性测试，不代表已经存在的业务基线：

1. 至少 70% 的首次测试用户能在 60 秒内完成第一条记录；
2. 至少 90% 的测试用户无需指导即可理解“情绪单选、活动多选”；
3. 记录过内容的测试用户中，至少 30% 会在七天内主动打开内容库或心情日历回看；
4. 正常存储空间下，结构化记录保存成功率达到 99%；
5. 媒体保存失败时，100% 给出明确原因和恢复路径，不静默丢失记录；
6. 100% 的核心交互可通过键盘完成，移动端触控目标不小于 44×44px；
7. 情绪数据不参与骰子、XP、角色等级和排行榜计算。

### 4.4 非目标

MVP 不包含：

- 好友、关注、点赞、评论或公开朋友圈；
- 匿名树洞与公开内容流；
- AI 情绪分析、AI 陪伴或心理诊断；
- 用户自定义情绪和活动；
- 音乐平台接入或音乐链接收藏；
- 情绪统计报表、相关性分析和月度总结；
- 强制提醒、连续打卡奖励或断签惩罚；
- 云同步、跨设备账号同步和端到端加密服务；
- 情绪状态驱动任务奖惩或任务难度自动调整。

## 5. Market Segments

市场按用户需要解决的问题划分，而不是按年龄或身份划分。

### 5.1 快速留痕者

**任务：** “我现在有一种明确感受，想在十几秒内留下它，不想写长日记。”

需要：快速情绪选择、活动标签、一键保存、默认当前时间。

### 5.2 多媒体记录者

**任务：** “这张照片、这段视频或这段语音代表我此刻的感受，我希望以后还能理解它为什么重要。”

需要：媒体与情绪记录绑定、封面预览、来源记录跳转。

### 5.3 阶段回顾者

**任务：** “我想知道某一天发生了什么、当时是什么状态，而不只是看到一个情绪分数。”

需要：心情日历、当天记录列表、完整详情和时间顺序。

### 5.4 私密表达者

**任务：** “有些话不适合发朋友圈，也不想打扰别人，但我需要一个安全的地方放下它。”

需要：默认私密、无社交压力、应用内清晰的存储和删除说明。

## 6. Value Propositions

### 6.1 核心价值主张

> 用一个情绪留下此刻，用日记、图片、视频和声音保存完整生活；以后从任何内容或日期，都能回到那一天。

### 6.2 相对竞品的差异

| 维度 | 常见心情打卡 | 常见多媒体日记 | Dice Life 情绪模块 |
|---|---|---|---|
| 记录门槛 | 低 | 中到高 | 低，只有情绪必选 |
| 同日多次记录 | 部分支持 | 支持 | 支持，并保留时间顺序 |
| 情绪表达 | 简单分数或表情 | 较弱 | 单一具体情绪 + 多活动上下文 |
| 多媒体 | 较弱 | 强 | 文字、图片、视频、语音 |
| 内容收纳 | 以记录列表为主 | 以日期为主 | 自动拆分为日记与媒体内容库 |
| 日历回看 | 情绪色块 | 日期索引 | 最后情绪 + 当天记录数量 + 完整记录 |
| 社交压力 | 通常无 | 通常无 | 完全私密，无好友系统 |
| 成长产品连接 | 无 | 无 | 属于 Dice Life，但不参与奖惩评分 |

### 6.3 Value Curve

重点提高：记录速度、多媒体上下文、内容回看、私密性、情绪表达温度。  
有意降低：复杂统计、公开社交、填写负担、强制打卡、游戏化奖惩。

## 7. Solution

### 7.1 信息架构

情绪模块内部有三个一级页签和一个全局新增入口：

```text
情绪状态 MIND STATUS
├── 日记：当前状态 + 按日期分组的记录时间轴
├── 内容库
│   ├── 全部：日记、图片、视频、语音内容
│   ├── 日记：只显示包含文字的记录
│   └── 媒体：只显示图片和视频
├── 心情日历：月历 + 日期详情
└── 记录感受：新增记录
```

桌面端页签位于模块标题下方；移动端使用底部模块导航，并为全局新增按钮预留安全区。主项目的全局导航结构保持不变。

### 7.2 核心用户流程

#### 流程 A：新增一条情绪记录

```text
进入情绪模块
→ 点击“记录感受”
→ 选择一个系统预设情绪（必选）
→ 选择零个或多个活动
→ 可选填写文字
→ 可选添加图片、视频或录制语音
→ 保存
→ 记录进入今日日记时间轴
→ 内容自动进入内容库
→ 该记录成为当天最新“当前状态”
```

#### 流程 B：从内容库回到原始记录

```text
进入内容库
→ 选择全部 / 日记 / 媒体
→ 点击一篇日记、一张图片或一段视频
→ 打开来源记录详情
→ 页面定位到被点击的内容
```

#### 流程 C：从心情日历回看

```text
进入心情日历
→ 日期格显示当天最后一条情绪和记录数量
→ 点击日期
→ 打开当天全部记录列表
→ 点击其中一条
→ 打开记录详情
```

### 7.3 功能需求

#### F-01 日记首页

- 默认进入日记页；
- 顶部展示当天最新一条记录作为“我现在”；
- 当前状态显示情绪、活动、时间和情绪图标；
- 当前状态只在记录发生的本地自然日内有效；
- 次日打开时不显示昨日为当前状态，但昨日记录永久保留；
- 下方记录按日期分组、时间倒序排列；
- 同一天允许任意多条记录；
- 点击记录进入统一记录详情。

#### F-02 新增记录

- 情绪必选，且每条记录只能选择一个；
- 活动可多选，也可不选；
- 文字、图片、视频和语音均为可选；
- 创建时间默认为保存时的本地时间；
- MVP 不支持创建时修改日期或补记历史；
- 未选择情绪时，保存按钮保持不可用并提供文字说明；
- 关闭存在未保存内容的编辑器时，需要二次确认；
- 保存过程中禁用重复提交，并显示明确进度。

#### F-03 系统预设情绪

系统按感受类型分组，用户最终仍只选择一个具体情绪：

| 分组 | 预设情绪 | 图标语言 | 建议浅色背景 |
|---|---|---|---|
| 愉悦 | 开心、兴奋、感激、满足 | 阳光、气球、爱心、星星 | 暖黄 |
| 平稳 | 平静、放松、专注 | 植物、海岛、光点 | 薄荷绿 |
| 低能量 | 疲惫、无聊、低落、孤独 | 低电量、发呆云、细雨、单人小岛 | 淡紫 / 雾蓝 |
| 高压力 | 焦虑、压力、生气、迷茫、悲伤 | 乱线、重物、火山、问号、雨滴 | 浅珊瑚 / 雾蓝 |

要求：图标使用 Dice Life 原创 SVG/插画资产，学习微信状态“图形隐喻 + 简短名称”的表达，不直接复制微信素材，也不使用系统字体 Emoji 作为最终产品资产。

#### F-04 系统预设活动

活动允许多选，MVP 只提供系统预设：

| 分组 | 活动 |
|---|---|
| 工作学习 | 工作、会议、学习、上课、通勤 |
| 日常生活 | 吃饭、做饭、家务、购物、旅行 |
| 身体恢复 | 睡眠、休息、散步、运动、生病 |
| 人际关系 | 独处、家人、朋友、伴侣、社交 |
| 兴趣娱乐 | 阅读、电影、游戏、音乐、创作 |

预设顺序固定；MVP 不支持新增、改名、排序和停用。

#### F-05 文字日记

- 支持纯文本；
- 文本为空时仍可保存；
- 建议软上限 5,000 字，超过后阻止保存并显示剩余字数；
- 列表展示最多三行，详情展示全文；
- 内容库“日记”只收录文本非空的记录。

#### F-06 图片与视频

- 支持从设备选择图片和视频；
- 图片格式：JPEG、PNG、WebP；单文件不超过 8MB；
- 视频格式以浏览器可播放格式为准；单文件不超过 80MB、时长不超过 3 分钟；
- 每条记录最多 9 张图片，视频最多 1 个；
- 上传前校验类型、大小和数量；
- 列表使用压缩预览或缩略图，详情加载原文件；
- 媒体失败不能导致已填写的情绪和文字丢失。

上述限制为 MVP 假设，需要通过设备存储测试确认。

#### F-07 语音

- 通过浏览器麦克风录制；
- 首次使用时请求麦克风权限；
- 单条记录最多一段语音；
- 最长 10 分钟、最大 20MB；
- 录制中显示时长、停止和取消；
- 保存前允许试听和重新录制；
- 权限被拒绝时说明如何恢复权限，不影响其他内容保存。

#### F-08 自动内容库

- 保存记录后，文本、图片、视频和语音自动出现在“全部”；
- 文本非空的记录出现在“日记”；
- 图片和视频出现在“媒体”；
- 语音在“全部”和来源记录详情中展示，MVP 不设独立语音页签；
- 内容项显示来源日期、情绪和内容类型；
- 点击内容项打开来源记录详情；
- 支持给整条记录或单个附件标记“珍藏”；
- 支持按“全部珍藏”筛选。

#### F-09 心情日历

- 默认显示当前月份；
- 支持切换前后月份；
- 有记录的日期展示当天最后一条记录的情绪图标；
- 同一天多条记录时显示数量角标；
- 无记录日期保持中性空状态，不使用“断签”文案；
- 点击有记录日期进入当天记录列表；
- 点击无记录日期不自动创建记录，可显示“这一天还没有记录”；
- 当天列表按时间倒序展示全部记录。

#### F-10 统一记录详情

- 展示时间、情绪、活动、全文、图片、视频和语音；
- 支持编辑情绪、活动和文字；
- 支持新增或删除附件；
- 支持珍藏记录或附件；
- 删除记录需要确认；
- 删除成功后提供短暂撤销入口；
- 从日记、内容库和日历进入时，返回后恢复原视图和滚动位置。

#### F-11 搜索

MVP 不提供全局搜索。内容量增长后在 P1 增加按文字、情绪、活动和日期搜索。

### 7.4 数据规则

一条 `EmotionEntry` 是唯一事实来源。日记时间轴、当前状态、内容库和日历均由记录数据计算，不复制生成多套内容。

```text
EmotionEntry
├── id
├── createdAt / updatedAt
├── moodId（单选）
├── activityIds（多选）
├── note（可空）
├── attachments[]
│   ├── image
│   ├── video
│   └── audio
└── isFavorite
```

- “当前状态” = 本地今天创建的最新一条记录；
- “某日代表情绪” = 该日创建时间最晚记录的情绪；
- “日期记录数” = 该自然日全部记录数量；
- 内容库项目保留 `sourceEntryId`，永远能回到来源记录；
- 删除来源记录时同时删除其媒体元数据和二进制文件。

### 7.5 空状态与异常处理

| 场景 | 产品行为 |
|---|---|
| 从未记录 | 展示温和引导和唯一主按钮“记录第一次感受” |
| 今天没有记录 | 不显示过期当前状态，展示“今天还没有记录” |
| 内容库为空 | 解释内容会在保存记录后自动出现 |
| 月历无记录 | 保持中性，不显示失败、断签或落后 |
| 媒体格式不支持 | 指出具体文件和支持格式，保留表单其他内容 |
| 存储空间不足 | 阻止媒体保存，允许用户移除媒体后仅保存结构化记录 |
| 麦克风权限拒绝 | 提供恢复权限说明，文字/图片/视频仍可使用 |
| 本地数据损坏 | 备份损坏原文、恢复安全空状态并向用户说明 |

### 7.6 隐私与安全

- MVP 数据只保存在当前浏览器本地；
- 页面必须明确说明“清理浏览器数据可能导致记录丢失”；
- 结构化记录与媒体二进制分开存储；
- 不向第三方发送日记、情绪和媒体；
- 不使用记录训练 AI；
- 通知和页面标题不展示敏感日记正文；
- 删除操作覆盖元数据和对应本地媒体；
- P1 再评估导出、备份、云同步与端到端加密。

### 7.8 Technology

- React 18 + TypeScript；
- Vite；
- Vitest + Testing Library；
- 结构化数据使用带版本号的本地存储；
- 图片、视频和语音使用 IndexedDB 保存二进制数据；
- 不在 `localStorage` 中保存 Base64 大媒体；
- 媒体访问通过可替换 Repository 接口封装，为未来云存储保留边界；
- 情绪模块代码独立放入 `src/emotion/`，避免继续扩大 `src/App.tsx`。

### 7.9 Assumptions

- 用户接受 MVP 只在当前设备和浏览器保存；
- 大多数记录包含少量文本或少量媒体，而不是长视频仓库；
- 预设的 17 个情绪和 25 个活动足以验证核心记录流程；
- 用户希望同日多次记录，并接受日历用最后一条情绪代表当天；
- 用户能理解“内容库是自动收纳，不是只有主动收藏才出现”；
- 黄色主操作与多种情绪色可以同时保持清晰品牌层级。
