## 安全审查结论

审查发现并修复：

1. **High：** 短链接会让服务端访问用户提供的 URL，且普通 fetch 无法把 DNS 校验结果绑定到连接。修复为完全移除服务端短链接访问，只从精确官方单曲链接提取 ID，再访问固定端点。
2. **High：** Serverless 入口信任任意 `X-Forwarded-For`，可绕过内存限流。修复为不使用该头作为客户端身份；生产多实例仍要求网关/共享限流。
3. **Important：** 请求超时只覆盖收到响应头前，慢速正文可悬挂。修复为正文流总时限并在超时/超限时取消 reader。
4. **Important：** 前端未中止换链接或卸载后的请求，且未校验服务端返回字段。修复为 AbortController 与严格响应契约。
5. **Important：** 已存历史记录中的危险封面 URL 可直接进入 img。修复为渲染时再次执行 provider 图片域名白名单；加载失败显示稳定占位。
6. **Important：** 限流桶可无界增长。修复为最大客户端桶数与窗口淘汰。

无音频下载、缓存或代理；错误不返回堆栈、上游正文、内部地址或敏感请求头；未开放 CORS。

## 残余风险与限制

- 固定上游使用 Node fetch，未使用可绑定预验证 IP 的自定义 dispatcher。当前通过“不接受用户可控 hostname、不访问短链、不跟随上游跳转”收缩风险；若未来开放短链，必须先实现可控 DNS/transport。
- 内存限流在 serverless 多实例间不共享，生产必须加网关或共享限流。
- 平台公开 JSON 结构可能变化；适配器会结构化失败，需替换对应 provider。
- 不支持歌单、专辑、播客、个人主页、搜索页或音频播放地址。
- 真实系统 DNS、iOS/Android 浏览器和生产 Serverless 平台仍需发布环境复核。
