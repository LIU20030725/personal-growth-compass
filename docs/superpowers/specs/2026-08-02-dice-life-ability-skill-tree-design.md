# Dice Life 能力技能树模块设计

> 状态：已完成产品讨论，等待书面规格复核
> 日期：2026-08-02
> 范围：能力模块初始版本（手动技能树）及后续 AI 扩展契约
> 相关调研：[能力模块竞品调研与产品启示](../../2026-08-01-能力模块竞品调研与产品启示.md)

## 1. 目标

能力模块用于长期建设个人的主技能、副技能和探索技能。用户可以创建不限数量的技能树，规划技能之间的前置关系，记录当前学习状态，关联执行任务，并用轻量成果记录证明真实成长。

模块不只是待办清单，也不只是技能展示图。它需要形成以下闭环：

```text
建立技能树 → 选择当前重点 → 推进技能节点 → 关联现实任务 → 用户确认掌握 → 记录真实成果
```

## 2. 产品基线

### 2.1 直接借鉴 SkillTree 的部分

以 [SkillTree – Learn Anything](https://www.skilltreeapp.com/) 为核心产品基线，不重新设计以下能力：

- 技能节点与依赖边组成技能树；
- 前置节点决定后续节点是否可开始；
- 节点使用“锁定、可开始、成长中、已掌握”四种状态；
- 完成前置节点后，后续节点自动解锁；
- 技能树生成或创建后仍可持续编辑；
- 整棵树通过颜色和状态呈现成长进度；
- 树是用户长期维护的个人资产，而非一次性计划。

### 2.2 Dice Life 的必要改造

- 不采用可自由拖拽、缩放和整理坐标的无限画布；
- 改为系统自动排布的固定“冒险路线树”；
- 增加主技能、副技能、探索技能和归档角色；
- 增加阶段顺序和阶段内并行分组；
- 技能节点可关联现有任务；
- 增加用户手动填写的轻量成果记录；
- 少量重大成果可由用户主动展示为树上的特殊节点。

### 2.3 视觉参考

技能树形态参考 [Fives — Career Skill Tree](https://dribbble.com/shots/20164209-Fives-Career-Skill-Tree)：

- 中央主干表达成长阶段；
- 左右分支表达同一阶段可并行发展的能力；
- 已掌握、成长中、未解锁和成果节点具有清晰视觉差异；
- 整体具有 RPG 成长路线感，但仍保持 Dice Life 明亮、硬边、轻像素化的现有风格。

## 3. 已确认的产品决策

1. 用户可以创建任意数量的技能树，不设置产品数量上限。
2. 用户可以置顶当前重点技能树，系统建议保持 1—3 棵，但不设置硬上限。
3. 首页必须直接出现技能树，体现能力模块的核心特色。
4. 首页采用“重点树舞台 + 技能库”：一次展示一棵重点树，其他技能用于快速切换。
5. 点击其他技能后，路由和主舞台同时切换为对应技能树。
6. 主技能、副技能和探索技能共用同一数据结构，只是当前角色不同。
7. 任务代表现实行动，不能直接等同于能力掌握。
8. “已掌握”最终必须由用户确认。
9. 初始版本的掌握标准由用户填写。
10. 初始版本的成果由用户手动填写，不做自动识别、复杂分类或平台同步。
11. 普通成果附属于技能或节点；重大成果只有在用户主动选择后才展示在树上。
12. AI 相关能力不进入初始版本，只保留接口、数据协议和模块边界。
13. V1 不为每个节点设置独立的 Lv.1—Lv.10 数值；节点成长由四种状态、掌握标准和真实成果表达，避免等级与掌握语义重复。

## 4. 版本范围

### 4.1 V1 初始版本包含

- 无限数量的技能树；
- 创建、编辑、归档和恢复技能树；
- 主技能、副技能、探索技能角色；
- 重点技能置顶和排序；
- 重点树主舞台与完整技能库；
- 固定自动布局的冒险路线树；
- 技能节点与前置依赖；
- 四种节点状态和自动解锁；
- 学习阶段与阶段内并行分组；
- 用户填写的掌握标准；
- 节点与现有任务的关联；
- 用户填写的轻量成果记录；
- 用户将重大成果展示在树上；
- 本地持久化、数据校验和版本迁移基础。

### 4.2 V1 明确不包含

- AI 入口或 AI 对话；
- 节点 XP 或 Lv.1—Lv.10 数值等级；
- API Key、模型供应商和模型选择；
- 自动生成技能树；
- 自动拆解实施计划；
- 自动生成掌握标准；
- 自动调整已有技能树；
- 自动抓取粉丝、收入、点赞或其他外部指标；
- 成果的复杂分类、评分或验证；
- 社区模板、公开分享或多人协作；
- OpenAI、Anthropic、Gemini 等厂商 SDK。

## 5. 信息架构与路由

### 5.1 能力模块入口

建议使用以下路由：

```text
/ability                         能力模块入口；打开最近访问或首个重点技能树
/ability/trees/:skillTreeId      显示指定技能树
```

`/ability` 在存在技能树时跳转到以下优先级最高的树：

1. 最近访问的重点技能树；
2. 排序第一的重点技能树；
3. 最近更新的未归档技能树；
4. 若不存在技能树，显示手动创建空状态。

切换技能树时更新 URL，刷新页面后仍停留在同一棵树。

### 5.2 首页结构

能力首页由两层组成：

1. **重点树舞台**
   - 占据首屏主要空间；
   - 展示当前技能树的主干、分支、状态和整体进度；
   - 旁边展示置顶技能的快速切换列表；
   - 显示当前阶段、下一步和最近成果摘要。
2. **完整技能库**
   - 搜索技能树或节点；
   - 按全部、主技能、副技能、探索和已归档筛选；
   - 按最近更新、用户排序或名称排序；
   - 每张卡片显示角色、节点进度、当前阶段和最近成果。

首页不同时渲染多棵完整技能树，以避免视觉混乱和性能浪费。

### 5.3 单棵技能树结构

- 顶部：返回能力图鉴、技能名称、角色、进度和主要操作；
- 中部左侧：固定自动布局的完整技能树；
- 中部右侧：当前选中节点的详情面板；
- 节点详情包括描述、状态、掌握标准、关联任务和手动成果；
- 点击节点只更新详情面板，不离开当前技能树；
- 移动端将详情面板改为底部抽屉或独立详情层。

## 6. 技能树布局规则

### 6.1 桌面端

- 按学习阶段从上到下排列；
- 每个阶段拥有一个中央主干位置；
- 同一阶段的并行节点在主干左右分布；
- 依赖边由系统自动计算，不存储用户坐标；
- 重大成果节点使用特殊外观，但仍遵循自动布局；
- 用户可以折叠阶段、筛选状态或聚焦当前阶段；
- 用户不能拖动节点到任意坐标。

### 6.2 移动端

- 转为纵向阶段路线；
- 每个阶段是一段可展开内容；
- 同阶段并行节点横向排列或换行；
- 默认突出当前阶段和下一步；
- 提供“查看完整路线”，但不要求用户在小屏上操作大型画布。

### 6.3 大型技能树

- 默认完整保留树结构，不限制节点数量；
- 支持折叠已掌握阶段；
- 支持只看当前阶段、成长中或未解锁节点；
- 搜索结果自动展开并定位到目标节点；
- 布局算法必须是确定性的，相同数据每次产生相同布局。

## 7. 节点状态规则

### 7.1 四种展示状态

```text
locked       锁定：至少一个前置节点未掌握
available    可开始：全部前置节点已掌握，但用户尚未开始
in_progress  成长中：用户主动开始，或关联了进行中的任务
mastered     已掌握：用户确认自己满足掌握条件
```

`locked` 是根据依赖关系计算的展示状态，不直接作为唯一事实写入数据。根节点在未归档时默认为 `available`。

### 7.2 掌握确认

- V1 的掌握标准由用户创建和编辑；
- 标准全部满足时，系统提示用户确认掌握；
- 系统不会自动把节点改为已掌握；
- 用户可以在标准未全部勾选时提前确认，但必须填写简短说明；
- 掌握后自动重新计算所有直接和间接后续节点的解锁状态。

### 7.3 撤销掌握

- 用户可以将已掌握节点退回成长中；
- 已经解锁或推进过的后续节点不强制回锁；
- 后续节点显示“前置条件发生变化”提醒；
- 系统不得删除后续节点的任务、成果或历史。

## 8. 阶段与并行计划

### 8.1 阶段

阶段表达大的成长顺序，例如：

```text
阶段 1：基础认知
阶段 2：核心能力
阶段 3：独立实践
阶段 4：稳定产出
```

每个阶段包含名称、排序和可选目标描述。阶段之间按顺序展示，但真正的解锁仍以节点依赖为准。

### 8.2 并行分组

- 并行分组只能包含同一阶段的节点；
- 并行分组表示这些节点可以在同一时期推进，不代表必须同时开始；
- 一个节点在同一阶段最多属于一个显式并行分组；
- 未加入分组的节点仍可根据依赖关系单独推进。

## 9. 任务关联

- 能力模块复用现有任务系统，不重新实现任务引擎；
- 一个任务可以关联一个或多个技能节点；
- 一个技能节点可以关联多个任务；
- 任务完成只更新行动记录和掌握标准的参考状态；
- 任务完成不会直接把技能标记为已掌握；
- 删除关联只删除关系，不删除任务本身；
- 归档技能或节点时保留任务历史。

## 10. 成果记录

### 10.1 V1 成果字段

- 成果名称；
- 日期；
- 简短说明；
- 关联技能树；
- 可选关联技能节点；
- 是否展示在树上。

V1 不要求成果类型、外部验证、自动指标、评分、附件或平台授权。

### 10.2 树上展示

- 普通成果只在节点详情和技能树摘要中出现；
- 用户可以将重要成果设置为“展示在技能树上”；
- 展示后的成果以特殊节点形式出现；
- 取消展示不会删除成果；
- 成果节点不参与前置解锁，也不能成为其他技能节点的必需依赖。

## 11. 数据模型

以下为产品层数据结构，字段命名可在实施计划中按现有代码规范调整。

```ts
type SkillRole = 'main' | 'side' | 'exploring'
type SkillTreeStatus = 'active' | 'archived'
type NodeProgress = 'available' | 'in_progress' | 'mastered'
type CriterionSource = 'manual' | 'ai'

interface SkillTree {
  id: string
  name: string
  description?: string
  role: SkillRole
  status: SkillTreeStatus
  focusedRank: number | null
  createdAt: string
  updatedAt: string
}

interface LearningPhase {
  id: string
  skillTreeId: string
  name: string
  description?: string
  order: number
}

interface SkillNode {
  id: string
  skillTreeId: string
  phaseId: string
  name: string
  description?: string
  progress: NodeProgress
  masteryNote?: string
  archivedAt?: string
  createdAt: string
  updatedAt: string
}

interface DependencyEdge {
  id: string
  skillTreeId: string
  prerequisiteNodeId: string
  dependentNodeId: string
}

interface ParallelGroup {
  id: string
  skillTreeId: string
  phaseId: string
  name?: string
  nodeIds: string[]
}

interface MasteryCriterion {
  id: string
  skillNodeId: string
  description: string
  satisfied: boolean
  source: CriterionSource
}

interface SkillTaskLink {
  id: string
  skillNodeId: string
  taskId: string
}

interface SkillOutcome {
  id: string
  skillTreeId: string
  skillNodeId?: string
  title: string
  description?: string
  occurredOn: string
  showOnTree: boolean
  createdAt: string
  updatedAt: string
}
```

V1 创建的 `MasteryCriterion.source` 始终为 `manual`，但字段现在保留，以避免未来 AI 功能迁移历史数据。

## 12. 核心模块边界

### 12.1 建议模块

```text
ability/
├─ model/        类型、Schema 与派生状态
├─ graph/        依赖校验、循环检测、解锁计算
├─ layout/       固定冒险树布局计算
├─ repository/   持久化、版本迁移与原子更新
├─ drafts/       草案校验与写入契约
├─ components/   技能库、树舞台、节点和详情面板
└─ routes/       能力入口与单树路由
```

各模块保持以下职责：

- `model` 不依赖 React；
- `graph` 只处理图关系，不处理页面状态；
- `layout` 输入树结构，输出确定性位置，不修改业务数据；
- `repository` 通过现有 `storageAdapter` 工作；
- `drafts` 同时服务 V1 手动创建和未来 AI 导入；
- UI 只消费这些模块，不自行实现图算法。

## 13. 持久化与迁移

- 使用现有 `storageAdapter`，V1 继续本地优先；
- 能力数据使用独立、带版本号的存储键，例如 `dice-life.ability.v1`；
- 每次更新先在内存中生成完整下一状态，通过校验后一次写入；
- 写入失败时保留旧数据，并向用户显示可恢复错误；
- 不设置技能树数量上限，但捕获浏览器存储配额错误；
- 未来新增字段必须通过显式迁移函数升级旧数据。

## 14. 校验与异常处理

### 14.1 保存前校验

- ID 唯一；
- 引用的技能树、阶段和节点存在；
- 依赖边不能跨技能树；
- 不允许节点依赖自身；
- 不允许重复依赖边；
- 不允许循环依赖；
- 并行分组中的节点属于同一技能树和同一阶段；
- 成果关联节点必须属于成果所在技能树；
- 归档节点不能作为新依赖的目标。

### 14.2 删除与归档

- 没有关联和历史的空节点可直接删除；
- 存在子节点、任务、标准或成果时，默认执行归档；
- 若用户坚持删除，必须先明确选择如何处理后续依赖；
- 删除技能树默认进入归档，不立即永久删除；
- 永久删除属于设置中的数据管理能力，不在日常树编辑流程中出现。

### 14.3 路由与数据异常

- URL 中的技能树不存在时返回能力入口并显示提示；
- 当前重点树被归档后自动切换到下一棵可用重点树；
- 没有技能树时显示手动创建引导；
- 图数据校验失败时不渲染错误结构，显示恢复入口并保留原始数据。

## 15. V1 草案契约与未来 AI 扩展

### 15.1 统一草案

手动创建流程和未来 AI 规划器都输出同一种中间结构：

```ts
interface SkillTreeDraft {
  tree: Omit<SkillTree, 'id' | 'createdAt' | 'updatedAt'>
  phases: DraftPhase[]
  nodes: DraftNode[]
  dependencies: DraftDependency[]
  parallelGroups: DraftParallelGroup[]
  masteryCriteria: DraftMasteryCriterion[]
  suggestedTasks?: DraftSuggestedTask[]
}
```

草案使用草案内局部 ID，`applyDraft()` 成功写入时再生成正式 ID。

### 15.2 规划器接口

V1 定义但不实现以下扩展接口：

```ts
interface AbilityPlanner {
  plan(input: AbilityPlanInput): Promise<SkillTreeDraft>
  expand(input: AbilityExpandInput): Promise<SkillTreeDraftPatch>
}
```

V1 不创建 AI 实例、不在 UI 中检查模型，也不安装厂商 SDK。

### 15.3 后续 AI 版本原则

- API 配置统一位于全局设置，不放在能力模块；
- 支持多厂商适配器；
- 使用项目专属 `ability-planner` Skill 约束访谈、拆解和输出；
- AI 可以新建整棵树或扩展现有分支；
- AI 生成阶段、依赖、并行组、任务建议和掌握标准；
- 掌握标准的 `source` 为 `ai`，但最终状态仍由用户判断和确认；
- 所有 AI 输出先经过结构校验与差异预览；
- AI 不得直接删除成果、修改用户掌握状态或覆盖正式技能树。

## 16. 测试策略

### 16.1 图引擎单元测试

- 根节点默认为可开始；
- 前置节点未掌握时节点锁定；
- 所有前置节点掌握后节点解锁；
- 多前置节点只完成部分时不解锁；
- 自依赖、重复边和循环依赖被拒绝；
- 撤销掌握不会删除或强制回锁已有后续进度；
- 跨技能树依赖被拒绝。

### 16.2 布局单元测试

- 相同输入产生相同位置；
- 阶段按顺序纵向排列；
- 并行节点分布在同一阶段；
- 成果节点不参与解锁拓扑；
- 空树、单节点、深链和宽分支均能布局；
- 折叠阶段后布局保持可读。

### 16.3 仓储与迁移测试

- 技能树创建、编辑、置顶、排序、归档和恢复；
- 刷新后数据完整恢复；
- 写入失败时旧快照保持不变；
- 非法快照不会覆盖已有合法数据；
- 版本迁移保持节点、任务链接和成果关系。

### 16.4 组件与集成测试

- `/ability` 选择正确的默认技能树；
- 点击其他技能更新路由和树舞台；
- 搜索、角色筛选和归档筛选；
- 点击节点打开对应详情；
- 用户创建和勾选掌握标准；
- 标准满足后提示确认，不自动掌握；
- 提前确认掌握时要求说明；
- 关联和解除任务不会删除任务；
- 添加成果并切换树上展示；
- 移动端阶段路线和节点详情可访问。

### 16.5 草案契约测试

- 手动草案通过统一 Schema；
- 非法依赖或缺失引用的草案被拒绝；
- `applyDraft()` 成功时一次生成完整技能树；
- `applyDraft()` 失败时不写入部分数据；
- 未来 AI 草案可在不修改正式树模型的情况下接入。

## 17. V1 验收标准

1. 用户可以创建任意数量的技能树并指定角色。
2. 用户可以置顶、排序、归档和恢复技能树。
3. 能力首页首屏展示一棵完整重点技能树。
4. 点击其他技能后，URL 和主舞台切换为对应技能树。
5. 用户可以手动创建阶段、节点、依赖和并行分组。
6. 系统拒绝循环依赖和非法引用。
7. 前置节点掌握后，后续节点自动解锁。
8. 系统不会自动宣布节点已掌握。
9. 用户可以创建掌握标准并最终确认掌握。
10. 用户可以把现有任务关联到技能节点。
11. 用户可以手动记录成果并选择是否展示在树上。
12. 刷新页面后所有树、节点、关系、任务链接和成果仍然存在。
13. 移动端不依赖自由画布即可浏览和操作技能树。
14. V1 不显示 AI 功能，也不依赖任何模型厂商 SDK。
15. `SkillTreeDraft` 与 `AbilityPlanner` 契约已经定义并有校验测试。
16. 技能节点只使用四种状态和掌握标准，不出现含义不清的数字等级。

## 18. 实施前置条件

进入实施计划前，需要先确认：

- 本规格是能力模块 V1 的唯一设计依据；
- 旧版 `career.skills`、`side.learning` 和 `side.achievements` 数据结构只作为迁移输入，不继续扩展；
- 实施计划需要单独说明旧数据如何转换为 `SkillTree`、`SkillNode` 和 `SkillOutcome`；
- 工作区现有任务模块和 `storageAdapter` 是需要复用的依赖，不重新实现。
