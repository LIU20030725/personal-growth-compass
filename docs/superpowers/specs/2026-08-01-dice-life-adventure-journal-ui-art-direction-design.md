# Dice Life 冒险日志 UI 美术风格设计规范

**版本：** 1.0  
**日期：** 2026-08-01  
**状态：** 视觉方向已确认，待实施  
**风格名称：** Pixel Documentary Journal · Bright Stage  

**上位规范：** [`STYLE.md`](../../../STYLE.md)  
**玩法依据：** [`2026-08-01-dice-life-adventure-journal-core-design.md`](./2026-08-01-dice-life-adventure-journal-core-design.md)

## 1. 设计结论

冒险日志采用「Dice Life 系统外壳 + 明亮像素纪录片主舞台」的融合方式。

全局 Header、Sidebar、字体、硬边框、实体阴影、金色操作和报表式信息秩序继续遵循项目现有 `STYLE.md`。像素纪录片风格只进入冒险日志内部的旅途场景、家园场景、人物、环境物件、发现内容和记忆叙事层。

最终体验应当像：

> 在一套清晰可靠的成长系统中，打开一扇通往明亮像素世界的窗口，把现实行动保存成一段能够回看的旅途纪录。

## 2. 风格继承关系

### 2.1 页面整体

整张页面的视觉权重建议为：

- Dice Life 硬边成长系统：60%。
- 像素纪录片自然场景：30%。
- 独立游戏的手工细节：10%。

必须保留的项目特征：

- 64px 固定 Header。
- 256px 固定 Sidebar。
- 浅灰白系统背景。
- 2px 深色硬边框。
- 2–4px 实体硬阴影。
- 金色主操作和当前状态。
- 中文主标题 + 英文微标签。
- 清晰的骰子余额、路线进度和建设状态。

### 2.2 像素场景内部

旅途和家园主舞台内部的视觉权重建议为：

- 明亮自然像素环境：60%。
- 纪录片取景与记忆信息：25%。
- Dice Life 状态浮层：15%。

像素场景可以柔和、诗意、自然，但场景外的功能组件仍需硬朗、清晰、可操作。

### 2.3 冲突处理

当本规范与 `STYLE.md` 冲突时：

1. 页面布局、功能信息和交互组件以 `STYLE.md` 为准。
2. 像素画布内部的色彩、景物和角色表现以本规范为准。
3. 不得为了加强像素游戏感而重做全局导航、角色侧栏或系统卡片。

## 3. 核心视觉关键词

### 3.1 主关键词

- 明亮自然。
- 诗意纪录。
- 像素旅行。
- 季节变化。
- 安静陪伴。
- 长期归属。
- 真实记忆。
- 手工质感。

### 3.2 次关键词

- 乡野道路。
- 森林、溪流和村落。
- 晴雨与昼夜变化。
- 摄影取景框。
- 日期、地点和观察编号。
- 声音采集。
- 阶段来信。
- 永久家园。

### 3.3 应避免的气质

- 阴沉灰绿和长时间低明度场景。
- 霓虹、高饱和糖果色和赛博朋克。
- 华丽魔法、粒子爆炸和战斗 HUD。
- 过度可爱、儿童化或玩具化。
- 写实 3D、照片级渲染和光滑矢量插画。
- 大面积旧纸、胶带和拼贴遮挡功能信息。
- 直接临摹任何特定游戏的角色、场景或 UI。

## 4. 页面空间结构

## 4.1 全局结构

冒险日志继续使用项目既有桌面布局：

```text
┌──────────────────────── Header 64px ────────────────────────┐
│ Dice Life        任务 / 成就 / 冒险日志             工具区 │
├──── Sidebar 256px ────┬────────────────────────────────────┤
│ 角色与系统模块         │ 页面标题 / 骰子余额                │
│                        ├────────────────────────────────────┤
│                        │ 旅途 / 家园切换                    │
│                        ├────────────────────────────────────┤
│                        │                                    │
│                        │       像素纪录片主舞台             │
│                        │          75%–80%                   │
│                        │                                    │
│                        ├────────────────────────────────────┤
│                        │ 发现记录或家园状态薄栏             │
└────────────────────────┴────────────────────────────────────┘
```

不得改变现有 Header 和 Sidebar 的位置、尺寸和基础视觉语言。

## 4.2 冒险日志内部

内部只保留两个一级切换：

- `旅途 JOURNEY`
- `家园 HOME`

主舞台要求：

- 占冒险日志容器约 75%–80% 的视觉面积。
- 在常见桌面分辨率下，场景应成为进入页面后的第一视觉焦点。
- 不使用永久右侧大面板挤压主场景。
- 路线、建设和信箱信息使用场景内小型硬边浮层。
- 发现记录和收藏摘要放入底部薄栏。

## 4.3 信息密度

一个场景画面内最多同时存在：

- 一个主状态浮层。
- 一个场景标题。
- 一组取景标记。
- 一个轻量环境控制入口。

次要数据进入底部薄栏或点击后展开，避免把风景重新变成数据仪表盘。

## 5. 色彩系统

## 5.1 系统层颜色

系统层完全继承 `STYLE.md`：

```yaml
system:
  background: "#f8f9fa"
  surface: "#ffffff"
  surface_container: "#edeeef"
  ink: "#191c1d"
  text_secondary: "#4d4732"
  outline_variant: "#d0c6ab"
  gold: "#ffd700"
  gold_dark: "#705d00"
  emerald: "#006c49"
  ruby: "#b91a24"
```

## 5.2 像素自然场景色板

首版采用明亮但不过度艳丽的晴日自然色：

```yaml
pixel_scene:
  sky_clear: "#83ced5"
  sky_highlight: "#a8dfe1"
  cloud: "#edf7ec"
  sun: "#ffd86b"
  sun_highlight: "#ffe995"
  mountain_far: "#83ad81"
  forest_mid: "#568966"
  grass: "#86ad6d"
  grass_dark: "#5f985c"
  path: "#e0c488"
  wood: "#5b4c32"
  house_cream: "#f0dca9"
  roof_rust: "#9f6948"
  accent_coral: "#c86446"
  character_teal: "#2f8290"
```

## 5.3 色彩使用原则

- 大面积天空和草地必须保持中高明度。
- 深绿色只用于前景树木、阴影和层次，不作为整页底色。
- 金色仍是系统操作色，不大面积铺入自然场景。
- 珊瑚红用于背包、邮箱和少量视觉锚点，不用于错误提示。
- 单张地图建议使用 12–24 个核心像素色，保持手工统一感。
- 天气变化可以降低饱和度，但不得长期把整个页面压成灰暗色调。

## 6. 字体与纪录片信息

### 6.1 系统字体

沿用项目字体：

- 大标题、章节标题：`Bebas Neue`。
- 正文、按钮和导航：`Bricolage Grotesque`。
- 中文环境使用系统中文字体作为回退。

### 6.2 纪录片微标签

日期、坐标、录音编号和观察编号使用系统等宽字体：

```css
font-family: ui-monospace, SFMono-Regular, Consolas, monospace;
font-size: 9px–11px;
font-weight: 700;
letter-spacing: 0.12em–0.16em;
```

示例：

- `REC · MEMORY 018`
- `FIELD LOCATION / 31.2°N`
- `CHAPTER 01 / SEASON OF BEGINNING`
- `SOUND NOTE 02 · 00:42`
- `HOME ARCHIVE · GOLDEN HOUR`

不使用像素字体承担长正文。像素感应来自场景资产，而不是牺牲文字可读性。

## 7. 形状、边框与层级

### 7.1 系统组件

- 主容器：`2px solid #191c1d`。
- 默认硬阴影：`4px 4px 0 #191c1d`。
- 小型浮层：`2px solid #191c1d` + `2–3px` 硬阴影。
- 主按钮：金色背景、深色边框和硬阴影。
- 主卡片圆角：0–4px。
- 场景内浮层不使用玻璃模糊。

### 7.2 场景画框

像素场景使用深色 2px 画框，四角加入简化摄影取景标记。取景标记只起纪录片提示作用，不模拟复杂相机操作。

场景画框外仍使用白色或浅灰系统容器，不能让像素景物无限延伸到整个 App 外壳。

### 7.3 场景内浮层

状态浮层使用实色或接近不透明的暖白色：

```yaml
scene_overlay:
  background: "#fffdf2"
  border: "2px solid #191c1d"
  shadow: "3px 3px 0 #191c1d"
  max_width: "240px–280px"
```

浮层面积不得超过主舞台的 20%。

## 8. 旅途页面美术规范

## 8.1 主画面

旅途是动态环境主舞台，应包含三个景深层次：

1. 远景：天空、云、山、远处村落或河流。
2. 中景：道路、林带、田野、桥梁或废弃建筑。
3. 前景：草叶、花朵、路牌、石头和短暂经过的动物。

角色通常位于画面中下部，占画面高度约 8%–14%。环境必须比角色更重要，让用户感觉自己在观察一段旅途，而不是操作一个主角。

## 8.2 动态内容

基础动态包括：

- 人物缓慢行走循环。
- 云层缓慢移动。
- 草木小幅摆动。
- 水面或光点的低频变化。
- 偶尔出现的鸟、落叶或远处炊烟。
- 天气与昼夜的缓慢过渡。

不使用：

- 高频闪光。
- 连续粒子爆炸。
- 镜头震动。
- 角色快速冲刺。
- 任务完成后强制切换场景。

## 8.3 纪录片层

旅途画面允许出现：

- 左上角 `REC` 和记忆编号。
- 左下角地点、章节和场景名称。
- 四角取景框。
- 底部观察记录薄栏。
- 环境音开关。

纪录片信息必须简短，不模拟完整相机 HUD，不显示光圈、快门、ISO 等与玩法无关的数据。

## 8.4 路线投资

当前路线信息使用主舞台右上角小型硬边浮层，包含：

- 当前章节。
- 下一地点名称。
- 已投入 / 所需骰子。
- 固定价格进度条。
- `投入骰子 INVEST` 主按钮。

浮层不得遮挡人物、关键道路或旅途发现。

## 8.5 旅途发现

发现记录使用底部横向薄栏，而非永久右侧列表。每项最多包含：

- 一个 30–36px 小像素缩略图或符号。
- 观察编号。
- 发现名称。
- 一行来源说明。

未解锁发现可以使用问号和中性色，但不使用锁链、红色警告或倒计时。

## 9. 家园页面美术规范

## 9.1 永久归属感

家园应明显是“同一个长期居所”，而不是每张地图重新生成的临时营地。

基础构成建议：

- 一座视觉稳定的主屋或帐篷小屋。
- 一个具有记忆意义的中心区域。
- 固定成长信箱。
- 若干可建设物件位置。
- 植物、照片、声音装置和旅途纪念物。

主屋轮廓和关键入口位置长期保持不变；季节、天气、植物状态和装饰可以变化。

## 9.2 画面气氛

家园默认使用晴日下午或金色时刻：

- 天空明亮。
- 窗户温暖。
- 草地与花朵具有更高生命力。
- 信箱使用珊瑚红和金色旗帜形成视觉锚点。

夜晚家园仍需保留足够亮度，依靠窗灯、月光和地面灯形成层次，不使用大面积纯黑。

## 9.3 建设信息

家园建设状态使用场景右上角小型硬边浮层：

- 同时展示 2–4 个正在建设的物件。
- 每个物件显示图标、名称、来源地图和投入进度。
- 已完成物件使用金色进度，不增加夸张奖励效果。
- 详细图纸列表通过点击展开，不长期占据主舞台。

## 9.4 成长信箱

信箱是家园中固定、不可移除的功能装置。

三种状态：

1. 平静：旗帜放下，保留轻微环境摆动。
2. 有新回顾：旗帜升起，露出信封，进入家园时出现一次柔和暖光。
3. 已阅读：暖光消退，旗帜恢复平静。

暖光使用金黄色低频明暗变化，不使用红点、数字角标、弹窗和催促声音。

## 10. 核心组件规范

## 10.1 旅途 / 家园切换

- 使用矩形硬边标签。
- 当前标签使用金色背景和金棕文字。
- 非当前标签使用白底黑边。
- 保持文字 `旅途 JOURNEY`、`家园 HOME`。
- 不使用圆角胶囊和底部移动端风格导航。

## 10.2 骰子余额

- 位于页面标题右侧或冒险日志顶部稳定位置。
- 使用白底硬边卡片。
- 骰子图标使用项目金色。
- 余额数字清晰，但不得比场景标题更抢眼。

## 10.3 投资按钮

```text
＋ 投入骰子 INVEST
```

- 金色实底。
- 2px 深色边框。
- 2–4px 硬阴影。
- 按下时位移并移除阴影。
- 不使用发光渐变或老虎机式动画。

## 10.4 环境音控制

- 使用轻量文字按钮：`♪ 环境音：开 / 关`。
- 首次播放必须由用户主动触发。
- 记住用户上次选择。
- 音乐、环境音和界面音效在正式实现中可分别控制。

## 10.5 地图切换

已解锁地图使用缩略照片或胶片目录展示，但外框仍为项目硬边卡片。

- 当前地图：金色边框或金色底部标记。
- 已解锁地图：正常可点击状态。
- 未解锁地图：展示名称、固定价格和路线顺序，不使用模糊图片诱导。
- 旧地图切换不播放大型解锁动画。

## 11. 像素素材规格

## 11.1 基础网格

- 环境 Tile：16×16px 或 32×32px。
- 角色基础 Sprite：24×32px、32×48px 或统一等比规格。
- 家园物件：16px 网格的整数倍。
- 所有像素素材必须使用整数倍缩放。
- 浏览器渲染使用 `image-rendering: pixelated`。

## 11.2 场景画布

桌面首版建议基础画布：

```yaml
canvas:
  reference_resolution: "960×520"
  aspect_ratio: "约 1.85:1"
  scale_mode: "nearest-neighbor / integer-friendly"
```

可根据实际内容区等比调整，但不得拉伸角色和物件。

## 11.3 动画规格

- 行走循环：4–8 帧。
- 待机循环：2–4 帧。
- 环境循环：建议 8–20 秒完成一次，避免明显机械重复。
- 信箱暖光：进入家园时播放一次，之后停止或降低频率。
- 动画帧率可以低于 60fps，保持像素手工感；UI 操作仍需流畅响应。

## 11.4 文件格式

- 像素 Sprite、Tile 和小物件优先使用 PNG。
- 大场景背景允许使用无损或高质量 WebP，但必须保持像素边缘。
- 动画可使用 Sprite Sheet、Canvas 或可控的序列帧。
- 不使用经过平滑插值的低清素材。

## 12. 地图美术模板

每张地图在制作前应填写：

```yaml
map_art_brief:
  chapter: "章节编号"
  title_cn: "中文地图名"
  title_en: "英文地图名"
  life_stage: "象征的人生阶段"
  season: "季节"
  time_of_day: "主要时段"
  weather: "基础天气"
  core_palette: "12–24 个核心颜色"
  landscape_layers:
    - "远景"
    - "中景"
    - "前景"
  ambient_motion:
    - "低频动态 1"
    - "低频动态 2"
  ambient_audio:
    - "主环境声"
    - "稀有声音"
  discoveries:
    - "25% 发现"
    - "50% 发现"
    - "75% 发现"
  home_blueprints:
    - "该地图开放的家园图纸"
```

首发地图方向示例：

- 晴日林径：开始行动、重新获得方向。
- 风过山谷：形成稳定节奏、接受缓慢变化。
- 海边公路：完成一个阶段、看见更远的空间。

## 13. 原创性与参考边界

项目可以参考纪录片旅行、16-bit 乡野冒险和独立游戏手工感，但正式资产必须形成自己的视觉识别。

制作时应使用特征描述：

- 明亮自然的 16-bit 像素景观。
- 纪录片式观察构图。
- 季节和声音记忆。
- 克制的乡村生活细节。
- 原创角色轮廓和原创地图地标。

不得直接复制或近似复刻特定作品的角色、建筑、图标、地图布局、字体标志或 UI 皮肤。

## 14. 动效与声音原则

### 14.1 目标

动效和声音用于制造“世界仍在缓慢呼吸”的感觉，不用于提高点击频率。

### 14.2 节奏

- 人物行走持续但缓慢。
- 环境变化低频、错峰发生。
- 页面打开后不连续弹出发现内容。
- 解锁反馈短而确定，不制造抽奖悬念。
- 用户停留越久不会获得更多资源。

### 14.3 声音

- 音乐以环境氛围和短旋律为主。
- 鸟鸣、溪水、风声和脚步需要保持低音量。
- 不使用金币雨、老虎机、战斗胜利或高频提示音。
- 页面失去焦点时降低或暂停非必要声音。

## 15. 可访问性与性能

- 所有文字与功能状态必须满足清晰对比度。
- 白色纪录片文字只放在具有足够深色背景或文字阴影的位置。
- 重要状态不能只依赖颜色、声音或动画表达。
- 支持系统“减少动态效果”：人物改为低帧待机，云和草木动态可暂停。
- 支持关闭音乐、环境音和界面音效。
- 页面不可见时暂停非必要 Canvas 或 Sprite 动画。
- 桌面首屏优先加载当前地图，旧地图和家园素材按需加载。
- 场景素材失败时显示静态占位，不影响骰子和进度操作。

## 16. 响应式策略

第一版优先桌面体验，并保持现有 Header 与 Sidebar 结构。

### 16.1 宽屏

- 主舞台充分扩展。
- 状态浮层保持 240–280px，不随画面无限放大。
- 底部记录薄栏横向展示。

### 16.2 中等桌面

- 减少主内容左右内边距。
- 浮层缩小至约 220–240px。
- 纪录片微标签可以隐藏次要坐标，但保留章节和场景名。

### 16.3 移动端后续原则

移动端不简单压缩桌面场景。正式适配时应另行设计：

- 主舞台保持横向取景或提供专用竖屏构图。
- 状态浮层改为底部抽屉。
- 旅途和家园切换保持可触达。
- 不在本版本范围内改变全局移动端导航。

## 17. 禁止事项

- 不改变现有全局 Header 和 Sidebar 的布局语言。
- 不把整个 App 像素化。
- 不用低饱和灰绿色覆盖整张冒险页面。
- 不用大面积纯黑制造夜晚。
- 不使用渐变作为系统容器主背景。
- 不使用玻璃拟态、模糊浮层和柔软漂浮卡片。
- 不让右侧信息面板长期占据超过 25% 的主舞台。
- 不用复杂相机参数制造伪纪录片感。
- 不使用战斗 HUD、血条、伤害数字和武器属性。
- 不用红点、倒计时和弹窗催促成长回顾。
- 不让视觉奖励遮挡真实任务和骰子来源。

## 19. 第一版视觉验收标准

1. 全局 Header、Sidebar、字体和硬边组件与现有 Dice Life 页面一致。
2. 进入冒险日志后，像素主舞台占内容区约 75%–80%。
3. 旅途和家园都以环境为第一视觉焦点，状态面板不得挤压场景。
4. 默认地图使用明亮自然色，不呈现整体阴沉或灰暗效果。
5. 大面积颜色保持中高明度，深色只用于轮廓、前景和层次。
6. 场景具有清晰的远景、中景和前景。
7. 人物占比克制，环境比角色更重要。
8. 场景具备日期、地点、记忆编号或声音记录等纪录片线索。
9. 纪录片信息不模拟无关的复杂相机参数。
10. 路线和建设状态使用小型硬边浮层，面积不超过主舞台约 20%。
11. 旅途发现和家园摘要使用底部薄栏，不设置永久大型侧栏。
12. 金色只用于系统主操作和当前状态，不铺满自然场景。
13. 家园能够明显表达永久归属，信箱是稳定的功能锚点。
14. 信箱新内容状态使用升旗、信封和一次暖光，不出现红点或弹窗。
15. 所有像素素材保持整数缩放和清晰边缘。
16. 音乐、环境音和动态效果均可关闭或降低。
17. 页面停留时间不产生任何资源或额外发现。
18. 视觉资产保持原创，不直接复刻参考作品的具体设计。

## 20. 实施边界

本文件定义冒险日志的 UI 美术方向，不代表已经修改正式页面。

正式实施前仍需单独完成：

- 旅途与家园页面线框图。
- 首发三张地图的美术 Brief。
- 角色、环境 Tile 和家园物件资产表。
- Canvas 或 Sprite 渲染方案。
- 场景动效与环境音性能预算。
- 桌面端交互原型和视觉验收截图。

只有在实施计划确认后，才将本规范应用到正式冒险日志代码。
